Rizika nešifrovaného webu

Proč je prosté HTTP nebezpečné?

Tři základní bezpečnostní hrozby na síťové cestě mezi klientem a serverem

Otázka u zkoušky

1. Odposlech (Eavesdropping)

Kdokoliv na trase (správce Wi-Fi v kavárně, ISP provider) vidí hesla, čísla karet i obsah zpráv v nešifrovaném čistém textu.

2. Podvržení (Man-in-the-Middle)

Útočník vstoupí doprostřed komunikace. Může pozměnit bankovní účet ve formuláři nebo podstrčit infikovaný skript.

3. Maskování (Impersonation)

Bez digitálního certifikátu klient nemá jistotu, zda skutečně komunikuje se svou bankou, nebo s podvodným phishingovým serverem.

Kryptografické základy

Symetrické vs. Asymetrické šifrování v TLS

Hybridní přístup: Asymetrická kryptografie pro výměnu klíče, symetrická pro přenos dat

Asymetrické šifrování (RSA / ECC)

  • Dva různé klíče: Veřejný klíč (Public key) pro šifrování, soukromý klíč (Private key) pro dešifrování.
  • Účel v TLS: Autentizace serveru a bezpečné předání společného relačního klíče (Session Key).
  • Nevýhoda: Matematicky extrémně náročné na CPU, nevhodné pro gigabajty dat.

Symetrické šifrování (AES / ChaCha20)

  • Jeden společný klíč: Stejný klíč šifruje i dešifruje data na obou stranách.
  • Účel v TLS: Bleskový šifrovaný přenos veškerého těla HTTP dotazů a odpovědí.
  • Výhoda: Hardwarově akcelerované moderními procesory (AES-NI), téměř nulová režie.
Navázání spojení

Průběh TLS 1.3 Handshake

Jak si klient a server vyjednají bezpečný kanál za pouhý 1 síťový obrat (1-RTT)

1. Client Hello

Klient pošle podporované verze TLS, seznam šifrovacích sad (Cipher Suites) a své parametry pro výměnu klíče.

2. Server Hello + Cert

Server vybere šifru, pošle své klíčové parametry a předloží digitální certifikát podepsaný certifikační autoritou.

3. Ověření a Spočtení

Klient ověří platnost certifikátu přes Root CA. Obě strany nezávisle spočítají identický symetrický klíč (Diffie-Hellman).

4. Šifrovaná data

Od tohoto okamžiku proudí veškerá data (včetně URL cesty, hlaviček i cookies) výhradně symetricky zašifrována!

Infrastruktura veřejného klíče (PKI)

Certifikační autority (CA) & Let's Encrypt

Řetězec důvěry od kořenové autority k doménovému certifikátu

Řetězec důvěry (Certificate Chain)

  • Root CA: Kořenová autorita, jejíž certifikát je pevně zabudován v operačním systému a prohlížeči.
  • Intermediate CA: Mezilehlá autorita podepsaná Root CA (izoluje kořenovou autoritu v offline trezoru).
  • Server Certificate: Certifikát domény (např. edu-portal.cz) podepsaný mezilehlou autoritou.

Revoluce Let's Encrypt (ACME protokol)

Nezisková certifikační autorita poskytující bezplatné doménové certifikáty (DV – Domain Validated). Pomocí protokolu ACME se obnova certifikátů na serveru provádí plně automaticky každých 60–90 dní (žádné ruční nákupy a instalace).

Hlavička HSTS (HTTP Strict Transport Security)

Zabraňuje útokům typu SSL Strip. Hlavička Strict-Transport-Security: max-age=31536000; includeSubDomains nařizuje prohlížeči, aby se na danou doménu po dobu jednoho roku připojoval VÝHRADNĚ přes HTTPS, i kdyby uživatel do adresního řádku napsal http://.

Shrnutí & Požadavky k absolutoriu

Co musíte bezpečně ovládat z okruhu č. 2 (HTTPS a bezpečnost)

Okruh absolutoria č. 2, 6

1. Význam HTTPS

Šifrování chrání proti odposlechu (Eavesdropping), podvržení dat (MITM) a zajišťuje identitu serveru.

2. Hybridní šifrování

Asymetrické pro autentizaci a výměnu symetrického klíče v handshake, symetrické pro bleskový přenos dat.

3. Řetězec důvěry PKI

Root CA → Intermediate CA → Server certifikát. Prohlížeč věří serveru, protože věří podpisové autoritě.

4. Hlavička HSTS

Vynucuje striktní HTTPS spojení bez možnosti uživatelského obejití varování při neplatném certifikátu.

Klasická otázka zkoušejícího

„Vidí útočník na Wi-Fi síti konkrétní navštívenou URL adresu, když komunikujete přes HTTPS?“
Správná odpověď: Vidí pouze doménu serveru (z IP adresy a z hlavičky SNI v TLS handshake, např. edu-portal.cz). Samotnou URL cestu (např. /student/vysledky-zkousek), parametry dotazu (query string), hlavičky i data formuláře nevidí, protože celá HTTP zpráva je již zašifrována!
