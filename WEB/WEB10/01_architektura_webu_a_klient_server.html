Architektura webu & Klient-Server model

Základní principy sítě World Wide Web, architektura klient-server, role prohlížeče a webového serveru, životní cyklus požadavku a srovnání statického vs. dynamického webu.

Základní paradigma

Principy architektury Klient-Server

Oddělení uživatelského rozhraní od aplikační a datové logiky

Otázka u zkoušky

1. Webový klient (User Agent)

Aplikace iniciující komunikaci (typicky webový prohlížeč – Chrome, Firefox, Safari, Edge, ale i vyhledávací bot nebo CLI nástroj curl):

  • Formuluje a odesílá HTTP požadavek (Request).
  • Přijímá HTTP odpověď (Response) od serveru.
  • Parcuje HTML, CSS, JavaScript a vykresluje výsledek na obrazovku (Rendering).
  • Zajišťuje interakci s uživatelem a běh klientských skriptů.

2. Webový server (Host)

Počítačový systém s veřejnou IP adresou a nepřetržitým během, který naslouchá na síťovém portu (port 80 pro HTTP, port 443 pro HTTPS):

  • Přijímá příchozí požadavky od tisíců klientů současně.
  • Ověřuje oprávnění, routuje cesty a spouští aplikační logiku.
  • Čte statické soubory z disku nebo dotazuje databázi.
  • Sestavuje a vrací HTTP odpověď se stavovým kódem a tělem zprávy.
Asymetrie modelu Klient-Server

Komunikaci v klasickém webovém modelu vždy iniciuje klient. Server je pasivní posluchač (Daemon) a bez předchozího požadavku klienta nemůže sám od sebe poslat data (výjimkou jsou moderní protokoly jako WebSockets).

Typy webových řešení

Statický web vs. Dynamický web

Rozdíl mezi soubory na disku a během serverových skriptů s databází

Vlastnost Statický web Dynamický web
Generování obsahu HTML kód je předem vytvořen a uložen na disku serveru. HTML kód se generuje v reálném čase za běhu skriptem (PHP, Node.js, Python).
Zátěž serveru Extrémně nízká (server pouze čte soubor z disku a posílá bajty do sítě). Vyšší (spotřeba CPU a RAM pro interpretaci kódu a databázové dotazy).
Personalizace Každý návštěvník dostává naprosto identický obsah. Obsah se mění podle přihlášeného uživatele, nákupního košíku, filtrů apod.
Databáze Není vyžadována (žádné SQL). Typicky vyžaduje relační či nerelační databázi (MySQL, PostgreSQL, Mongo).
Typické použití Prezentační weby, dokumentace, blogy (Astro, Hugo, 11ty). Informační systémy, e-shopy, sociální sítě, diskusní fóra.
Serverové technologie

Webový server: Software a architektura

Srovnání procesních (Apache) a událostmi řízených (Nginx, Node.js) serverů

Apache HTTP Server

Historický lídr webu. Využívá procesní / vláknový model (každé spojení má své vlákno). Velmi flexibilní díky souborům .htaccess a modulárnímu systému (mod_rewrite, mod_php).

Nginx (Engine-X)

Moderní asynchronní server řízený událostmi (Event-driven). Zvládne desítky tisíc souběžných spojení s minimální pamětí. Často slouží jako Reverse Proxy a zátěžový vyvažovač (Load Balancer).

Node.js / Aplikační servery

Serverový JavaScript s neblokujícím I/O. Samotný aplikační kód funguje jako HTTP server bez nutnosti externího webserveru (často běží za Nginxem jako proxy).

Co je to Reverse Proxy?

Obrácená proxy (např. Nginx) stojí před aplikačními servery. Zajišťuje terminaci šifrování HTTPS (SSL Offloading), servíruje statické assety, provádí kompresi Gzip/Brotli a rozděluje zátěž mezi více aplikačních nodů.

Komunikační řetězec

Život jednoho webového požadavku

Co přesně se stane od stisku Enteru v adresním řádku po zobrazení stránky

1. DNS Resoluce

Prohlížeč zjistí IP adresu k doméně (např. edu-portal.cz → 195.113.144.2) přes lokální cache a DNS servery.

2. TCP & TLS Handshake

Navázání spolehlivého TCP spojení (SYN-ACK) a následné šifrované vyjednání symetrického klíče TLS na portu 443.

3. HTTP Dotaz & Zpracování

Odeslání GET /index.html HTTP/1.1. Server požadavek vyhodnotí a vrátí odpověď se stavovým kódem 200 OK a HTML tělem.

4. Rendering v prohlížeči

Jádro sestaví DOM strom, stáhne CSS a obrázky, vytvoří Render Tree, spočítá layout a vykreslí pixely (Paint).

Okruh absolutoria č. 1

1. Klient-Server model

Asymetrická architektura: Klient odesílá požadavky (Request), server odpovídá (Response). Klient řídí prezentaci.

2. Statický vs Dynamický web

Statický web servíruje hotové soubory bez backendového výpočtu. Dynamický web generuje HTML za běhu z databáze.

3. Webový server & Reverse Proxy

Role serverů Apache a Nginx. Princip reverzní proxy pro vyvažování zátěže, SSL terminaci a cachování.

4. Cyklus Request-Response

Posloupnost kroků: DNS resoluce → TCP spojení → TLS handshake → HTTP Request → HTTP Response → DOM Rendering.

Typická záludná otázka zkoušejícího

„Je Single Page Application (SPA) vytvořená v Reactu či Vue statický, nebo dynamický web z pohledu webového serveru?“
Správná odpověď: Z pohledu webového serveru se jedná o statický web! Server pouze odesílá statický HTML soubor, CSS a zabalený JavaScript bundle. Veškeré dynamické generování HTML a routování probíhá až v prohlížeči uživatele (Client-Side Rendering – CSR).
