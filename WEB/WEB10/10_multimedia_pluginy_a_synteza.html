Nativní audio a video

Nativní multimédia v HTML5: <video> a <audio>

HTML5 odstranilo nutnost externích pluginů a zavedlo nativní podporu multimédií s přímou hardwarovou akcelerací a JavaScriptovým API.

Značka <video> a její atributy

  • controls: Zobrazí nativní ovládací prvky prohlížeče (play, pause, hlasitost, fullscreen).
  • poster: URL náhledového obrázku zobrazeného před spuštěním videa.
  • preload: Určuje způsob načítání (none, metadata, auto).
  • autoplay + muted: Automatické přehrávání moderní prohlížeče povolují výhradně se ztlumeným zvukem (muted).
  • <source>: Umožňuje definovat alternativní formáty pro různé prohlížeče (WebM, MP4).
  • <track>: Podpora titulků a kapitol ve formátu WebVTT.
Robustní vložení videa v HTML5
<video controls poster="preview.jpg" preload="metadata">
  <source src="video.webm" type="video/webm">
  <source src="video.mp4"  type="video/mp4">
  <track src="cs.vtt" kind="subtitles" srclang="cs" label="Čeština" default>
  Váš prohlížeč nepodporuje přehrávání videa v HTML5.
</video>

Značka <audio> a audio kodeky

Nativní audio přehrávač
<audio controls preload="none">
  <source src="podcast.opus" type="audio/ogg; codecs=opus">
  <source src="podcast.mp3"  type="audio/mpeg">
  Váš prohlížeč nepodporuje element audio.
</audio>
Kodek / Formát Výhody Využití
MP4 (H.264 / AAC) 100% kompatibilita, hardwarová podpora Univerzální standard
WebM (VP9 / Opus) Otevřený formát, vysoká komprese Moderní web, YouTube
MP3 Univerzální audio formát Zpětná kompatibilita
Opus / Ogg Špičková kvalita i při nízkém datovém toku Streaming hlasu, podcasty

Webová grafika

Vektorová grafika (SVG) vs. Rastr (<canvas>, obrázky)

Volba grafického formátu zásadně ovlivňuje rychlost načítání, ostrost na Retina displejích a možnosti animace.

SVG (Scalable Vector Graphics)

  • Formát: XML značky popisující křivky, přímky a tvary.
  • Škálovatelnost: Dokonale ostré při libovolném zvětšení a DPI.
  • DOM a CSS: Každá část SVG je element v DOM stromu; lze stylovat CSS a animovat JS.
  • Vhodné pro: Ikony, loga, diagramy, UI prvky.

<canvas> (Rastrové kreslení)

  • Formát: Prázdné rastrové plátno vykreslované procedurálně pomocí JavaScriptu (2D či WebGL/WebGPU).
  • Výkon: Vhodné pro tisíce objektů současně (hry, vizualizace částic, generativní grafika).
  • Nevýhody: Nemá DOM uzly, horší přístupnost pro čtečky, při změně rozlišení se musí překreslit.

Moderní rastrové formáty

  • WebP: O 25–35 % menší než JPEG při srovnatelné kvalitě. Podporuje průhlednost i animace.
  • AVIF: Extrémně efektivní komprese založená na AV1. Vynikající pro hero bannery a fotky.
  • Značka <picture>: Servíruje optimální formát dle podpory prohlížeče s fallbackem na JPEG.

Historie a bezpečnost

Úpadek a konec proprietárních pluginů (Flash, Silverlight)

Do příchodu HTML5 byl multimediální web závislý na binárních zásuvných modulech třetích stran. Proč musely definitivně zaniknout?

Kritické důvody konce éry pluginů

  • Závažné bezpečnostní díry: Adobe Flash Player, Java Applety a Microsoft Silverlight běžely mimo sandbox prohlížeče a byly nejčastějším terčem zero-day útoků a malware.
  • Mobilní revoluce (2007–2010): Steve Jobs odmítl povolit Flash na iOS (iPhone/iPad) kvůli obrovské spotřebě baterie, absenci dotykového ovládání a nestabilitě. Tím započal jeho pád.
  • Uzavřený proprietární kód: Web je postaven na otevřených standardech (W3C/WHATWG). Proprietární binárky v rukou jedné korporace odporovaly filozofii svobodného internetu.
  • Nepřístupnost: Obsah uvnitř Flash banneru byl pro vyhledávače (SEO) a screen readery neviditelnou „černou skříňkou“.

Čím HTML5 pluginy nahradilo?

Zastaralá technologie Moderní otevřená náhrada
Flash Video (FLV) <video> (MP4/H.264, WebM)
Flash animace / hry <canvas>, WebGL, CSS animace
Flash Audio / zvuky <audio>, Web Audio API
Java Applety WebAssembly (Wasm) + JavaScript
Silverlight Nativní HTML5 + EcmaScript

Oficiální konec podpory Adobe Flash byl celosvětově završen 31. prosince 2020 (End-of-Life).

Zkouškový checklist k absolutoriu

Závěrečný zkušební checklist modulu WEB10

Tento checklist pokrývá základní otázky okruhů 1 až 6 a 20 pro úspěšné složení zkoušky či absolutoria.

Okruhy 1 & 2

Vysvětlit komunikaci klient-server, princip TCP/IP, rozdíl HTTP/1.1 vs HTTP/2 a HTTP/3, metody GET/POST a význam stavových kódů (200, 301, 404, 500).

Okruhy 2 & 6

Popsat TLS handshake, certifikáty a autority, DNS stromovou hierarchii překladu domény a rozdíl mezi sdíleným hostingem, VPS a Cloud CDN.

Okruhy 3 & 4

Rozdíl HTML 4.01, XHTML a HTML5. Kostra dokumentu (<!DOCTYPE html>, <html>, <head>, <body>), význam kódování UTF-8 a hierarchie nadpisů.

Okruhy 5 & 20

Nativní značky <video> a <audio>, podpora formátů (MP4, WebM), rozdíl mezi vektorovým SVG a rastrovým Canvasem, důvody zániku Adobe Flash.

Typická syntetická otázka komise u absolutoria:

„Popište detailně, co vše se odehraje od okamžiku, kdy uživatel zadá do adresního řádku https://www.skola.cz a stiskne Enter, až po vykreslení stránky včetně videa v HTML5?“

Stručná osnova odpovědi: 1) Prohlížeč zkontroluje DNS cache a provede rekurzivní DNS dotaz na IP adresu. 2) Naváže se TCP spojení (3-way handshake) na portu 443 a proběhne TLS handshake (ověření certifikátu, ustavení symetrického šifrovacího klíče). 3) Prohlížeč odešle HTTP požadavek (GET /) a obdrží HTML odpověď se stavovým kódem 200 OK. 4) Parser sestaví DOM strom, narazí na externí zdroje (CSS, JS, obrázky, video) a vyšle další paralelní požadavky. 5) Element <video> začne načítat první datové chunky (metadata/hlavičku kodeku H.264/WebM) a prohlížeč spustí přehrávání na GPU vrstvě bez potřeby Flash pluginu.
