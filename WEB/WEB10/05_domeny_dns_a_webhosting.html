Jak funguje Domain Name System (DNS)

Globální telefonní seznam internetu: Překlad domény na číselnou IP adresu

Otázka u zkoušky

1. DNS Resolver

Lokální server vašeho poskytovatele (ISP) nebo veřejný resolver (1.1.1.1, 8.8.8.8), který přijme dotaz a provádí rekurzivní dohledání.

2. Root servery (.)

13 logických kořenových serverů na vrcholu hierarchie. Odkazují resolver na servery příslušné TLD domény.

3. TLD servery (.cz, .com)

Správci národních (ccTLD) nebo generických (gTLD) koncovek (např. CZ.NIC pro doménu .cz). Znají autoritativní servery domény.

4. Autoritativní servery

Konečný server hostingové společnosti, který uchovává přesnou zónu a konkrétní IP adresu (např. ns1.forpsi.cz).

Konfigurace DNS zóny

Základní typy DNS záznamů

Směrování webu, pošty, subdomén a ověřování doménového vlastnictví

Typ záznamu Cílová hodnota Účel a příklad konfigurace
A IPv4 adresa Směruje doménu na konkrétní webový server: edu-portal.cz → 195.113.144.2
AAAA IPv6 adresa 128bitová adresa nové generace: edu-portal.cz → 2001:718:1:1::2
CNAME Doménové jméno (Alias) Odkazuje subdoménu na jinou doménu: www.edu-portal.cz → edu-portal.cz
MX Mail Server + Priorita Určuje, kam doručovat e-maily: 10 mail.edu-portal.cz (nižší číslo = vyšší priorita)
TXT Textový řetězec Ověření vlastnictví domény (Google Search Console), zabezpečení pošty (SPF, DKIM, DMARC)
Hodnota TTL (Time to Live)

Doba v sekundách (např. TTL = 3600), po kterou si resolverské servery pamatují odpověď ve své paměti cache. Před plánovaným stěhováním webu se doporučuje snížit TTL na 300 sekund, aby se změna projevila po celém světě během 5 minut.

Serverová infrastruktura

Modely webhostingu: Sdílený vs. VPS vs. Cloud

Výhody, nevýhody, cenová náročnost a míra technické kontroly

1. Sdílený webhosting

Stovky klientů sdílejí jeden operační systém a webový server. Nízká cena, nulová správa serveru, ale omezený výkon a nemožnost instalace vlastních systémových balíčků (např. Node.js či Redis).

2. Virtuální server (VPS)

Virtualizovaný počítač (KVM) s garantovanými CPU jádry, RAM pamětí a plným přístupem správce (root). Vyžaduje znalost správy Linuxu, konfigurace firewallu a aktualizací zabezpečení.

3. Cloud & Serverless

Flexibilní zdroje účtované za reálné využití (AWS, GCP, Vercel). Automatické škálování při návalech návštěvníků, vysoká dostupnost (High Availability) a globální distribuce.

Metodika nasazení

Správa a Deployment: Od FTP ke Git CI/CD

Jak se změny z počítače vývojáře dostanou bezpečně na produkční server

Historický přístup: FTP / SFTP

  • Ruční kopírování souborů přes Total Commander nebo FileZillu.
  • Značná rizika: Riziko přepsání cizí práce kolegy, neexistence historie verzí, nutnost ručního nasazování bez automatických testů, nebezpečí nešifrovaného FTP přenosu hesel.

Moderní přístup: Git & CI/CD Pipeline

  • Vývojář odešle kód příkazem git push origin main.
  • Automatický runner (GitHub Actions, GitLab CI) spustí testy a lintery.
  • Po úspěšném průchodu proběhne automatické sestavení a nasazení na server bez výpadku (Zero-Downtime Deployment).

Okruh absolutoria č. 6

1. Hierarchie DNS

Resolver → Root servery (.) → TLD servery (.cz) → Autoritativní nameserver domény.

2. Rozdíl A vs. CNAME

Záznam A ukazuje přímo na IP adresu, zatímco CNAME je alias ukazující na jiné doménové jméno.

3. Hostingové modely

Sdílený hosting (jednoduchost, omezení) vs. VPS (root kontrola, nároky na správu) vs. Cloud.

4. Úloha TTL

Doba platnosti záznamu v mezipaměti cache. Klíčový parametr pro bezvýpadkové stěhování webu.

Typická záludná otázka zkoušejícího

„Lze vytvořit CNAME záznam pro samotnou kořenovou doménu bez subdomény (tzv. naked domain / apex domain např. edu-portal.cz)?“
Správná odpověď: Podle oficiální specifikace DNS (RFC 1034) to nelze! Kořenová zóna musí vždy obsahovat záznamy SOA a NS, a standard zakazuje, aby na stejném uzlu existoval CNAME společně s jinými záznamy. Pro kořenovou doménu se musí použít přímý záznam A/AAAA (nebo proprietární funkce jako CNAME Flattening / ALIAS u Cloudflare).
