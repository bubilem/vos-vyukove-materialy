Principy sítí CDN (Content Delivery Network)

Přiblížení obsahu uživateli: Jak překonat fyzické omezení rychlosti světla v optice

Otázka u zkoušky

Pokud je původní server (Origin Server) umístěn v Praze, návštěvníkovi ze Sydney by trval každý dotaz přes 250 ms jen kvůli vzdálenosti. CDN tento problém řeší sítí tisíců Edge serverů (PoP – Points of Presence) po celém světě.

1. Směrování Anycast

Jedna IP adresa je inzerována z desítek datacentier. Požadavek uživatele je automaticky nasměrován na geograficky nejbližší server.

2. Edge Caching

Statické soubory (obrázky, CSS, JS, fonty) se při prvním stažení uloží na Edge serveru. Všichni další návštěvníci v regionu je dostanou za pouhé 2–5 ms.

3. Úspora zátěže Originu

CDN odfiltruje až 90 % veškerého provozu. Původní aplikační server odbavuje pouze čistě dynamická API data.

Jak moderní brána chrání web před roboty a masivními útoky

Mitigace DDoS útoků

Distribuované útoky o síle stovek gigabitů či terabitů za sekundu (botnety) by běžný webhosting okamžitě vyřadily z provozu. Globální CDN kapacita (např. Cloudflare o síle 200+ Tbps) útočný provoz rozptýlí a absorbuje na svých hranových uzlech.

Web Application Firewall (WAF)

Inspekce příchozích HTTP dotazů v reálném čase. Automaticky blokuje známé útoky dříve, než dorazí na váš server:

  • SQL Injection (SQLi) a Cross-Site Scripting (XSS).
  • Blokování škodlivých scraper botů a brute-force útoků na přihlašovací formuláře.
  • Geografické filtrování (Geo-blocking).
Vývojářský ekosystém

Služby a auditní nástroje pro webdesignéry

Objektivní měření kvality, přístupnosti a rychlosti načítání

Google Lighthouse

Integrovaný auditní nástroj v Chrome DevTools. Hodnotí 4 pilíře: Výkon (Performance), Přístupnost (Accessibility), Osvědčené postupy (Best Practices) a SEO.

Core Web Vitals

Metriky přímo ovlivňující pozici ve vyhledávání Google:

  • LCP: Rychlost načtení největšího obsahu.
  • INP: Doba odezvy na kliknutí/interakci.
  • CLS: Stabilita layoutu (poskakování).

W3C Validátory

Oficiální nástroje pro kontrolu souladu s webovými standardy:

  • W3C Markup Validator (HTML).
  • W3C CSS Validation Service.
  • WAVE / axe DevTools pro přístupnost.
Moderní architektury

Architektura JAMstack & Headless CMS

Oddělení správy obsahu od uživatelského rozhraní pomocí API

Tradiční monolit (např. WordPress)

Databáze, administrace i vykreslování HTML běží na jednom serveru. Každý požadavek návštěvníka zatěžuje databázi a představuje potenciální bezpečnostní zranitelnost.

JAMstack (JavaScript + APIs + Markup)

Frontend je předem sestaven do statického HTML/CSS a nahrán přímo na globální CDN (Vercel, Netlify). Obsah se spravuje v Headless CMS (Strapi, Contentful) a načítá se přes REST nebo GraphQL API.

  • Maximální bezpečnost (žádná databáze vystavená do internetu).
  • Okamžité načítání přímo z Edge serverů po celém světě.

Shrnutí & Požadavky k absolutoriu

Co musíte bezpečně ovládat z okruhu č. 6 (Cloud a CDN)

Okruh absolutoria č. 6

1. Princip CDN sítě

Zkrácení fyzické vzdálenosti cachováním statických souborů na geograficky distribuovaných Edge serverech.

2. WAF ochrana

Aplikační firewall filtrující škodlivé dotazy (SQLi, XSS) a tlumící masivní DDoS útoky ještě před serverem.

3. Core Web Vitals

Metriky LCP (rychlost obsahu), INP (reakce na vstup) a CLS (vizuální stabilita) zásadní pro SEO a UX.

4. Headless přístup

Oddělení backendu (API + CMS) od prezentačního frontendu hostovaného jako statický web na CDN.

Typická otázka u absolutoria

„Jaký je rozdíl mezi cachováním v prohlížeči a cachováním na CDN?“
Správná odpověď: Prohlížečová cache (Browser Cache) je lokální v zařízení konkrétního uživatele a zrychluje jeho opakované návštěvy. CDN cache (Edge Cache) je sdílená na serveru v datacentru – jakmile si soubor stáhne první návštěvník z Prahy, všichni další návštěvníci z ČR jej dostanou okamžitě z CDN bez zatížení hlavního serveru.
