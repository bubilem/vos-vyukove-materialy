Princip preprocesingu a vývojový řetězec

Proč píšeme kód v preprocesoru, když prohlížeč rozumí pouze čistému CSS?

Otázka u zkoušky

CSS vzniklo jako jednoduchý jazyk pro formátování dokumentů. U velkých projektů o desítkách tisíc řádků však naráželo na absenci logiky, nemožnost rozdělení do modulů bez zbytečných HTTP požadavků a neustálé opakování kódu (porušení principu DRY – Don't Repeat Yourself).

1. Zdrojové soubory

Vývojář píše kód ve formátu .scss nebo .less rozdělený do přehledných komponent (_buttons.scss, _header.scss).

2. Kompilátor (Transpiler)

Nástroj (např. Dart Sass, Vite, Webpack) přeloží zdrojový kód do standardního validního CSS, odstraní komentáře a minifikuje výstup.

3. Source Maps (.map)

Generované mapovací soubory umožňují v DevTools prohlížeče vidět přesné číslo řádku v původním SCSS souboru i u zkompilovaného CSS.

Srovnání syntaxí

Proměnné a vnořování (Nesting)

Srovnání Sass (SCSS) vs. Less a klíčový referenční operátor &

scss • syntaxe sass 
$primary-color: #06b6d4;  /* Proměnná se znakem $ */

.card {
  padding: 1.5rem;

  /* Vnořený selektor potomka */
  .card-title {
    color: $primary-color;
  }

  /* & reprezentuje rodičovský selektor .card */
  &:hover {
    transform: translateY(-4px);
  }

  &--featured {
    border: 2px solid $primary-color;
  }
}
less • syntaxe less 
@primary-color: #06b6d4;  /* Proměnná se znakem @ */

.card {
  padding: 1.5rem;

  .card-title {
    color: @primary-color;
  }

  &:hover {
    transform: translateY(-4px);
  }

  &--featured {
    border: 2px solid @primary-color;
  }
}
Význam referenčního operátoru &

Znak & vkládá přesný název nadřazeného bloku. Umožňuje přirozeně vytvářet pseudotřídy (&:hover, &:focus) a metodiku BEM (&__element, &--modifier).

Znovupoužitelné bloky

Mixiny s parametry (Znovupoužitelnost)

Obdoba funkcí v programovacích jazycích aplikovaná na stylopis

scss • parametrický mixin 
/* Definice mixinu s výchozí hodnotou parametru */
@mixin glass-card($blur: 12px, $opacity: 0.05) {
  background: rgba(255, 255, 255, $opacity);
  backdrop-filter: blur($blur);
  border: 1px solid rgba(255, 255, 255, 0.1);
  border-radius: 14px;
}

/* Volání mixinu v konkrétních komponentách */
.user-profile-card {
  @include glass-card(16px, 0.08);
}

.site-navigation {
  @include glass-card(); /* Použijí se výchozí hodnoty */
}

Jak fungují mixiny v Less?

V preprocesoru Less se mixiny definují přímo jako CSS třídy:

.glass-card(@blur: 12px) {
  backdrop-filter: blur(@blur);
  border-radius: 14px;
}

.user-profile-card {
  .glass-card(20px);
}

Mixiny vloží celé deklarace přímo do cílového selektoru. Hodí se pro znovupoužitelné balíčky vlastností.

Modularizace a architektura

Partials, modularizace a rozdíl @mixin vs. @extend

Jak organizovat projekt bez degradace výkonu výsledného CSS

Partials a directiva @use (Sass 7-1 pattern)

Soubory s podtržítkem na začátku (např. _variables.scss, _cards.scss) se nekompilují samostatně, ale vkládají se do hlavního souboru main.scss:

@use "abstracts/variables" as vars;
@use "components/cards";

body {
  color: vars.$primary-color;
}

Klíčový rozdíl: @mixin vs. @extend

  • @mixin: Kopíruje celý kód deklarací do každého místa použití. Zvětšuje velikost CSS souboru, ale udržuje čistou specificitu.
  • @extend: Spojí selektory čárkou v CSS (.btn, .btn-submit { ... }). Nezvyšuje velikost kódu, ale může nechtěně nafouknout selektorový strom při nesprávném použití.
  • Moderní CSS dnes: Nativní CSS už umí proměnné i vnořování (CSS Nesting), preprocesor však stále dominuje v type-checkingu, smyčkách a velkých týmových projektech.

Okruh absolutoria č. 12

1. Co je preprocesor

Nástroj rozšiřující CSS o programovací konstrukce (proměnné, funkce, vnořování), který se kompiluje do čistého CSS.

2. Sass vs. Less proměnné

V Sassu začínají znakem $ (např. $color), v Lessu znakem @ (např. @color).

3. Operátor &

Odkazuje na nadřazený selektor. Klíč k tvorbě stavů (&:hover) a metodice BEM bez opakování kódu.

4. Mixiny vs. Partials

Mixiny jsou znovupoužitelné parametrické bloky kódů, partials (_nazev.scss) slouží k logické modularizaci souborů.

Typická otázka u absolutoria

„Jaký je rozdíl mezi proměnnou v Sassu ($color) a nativní CSS proměnnou (--color)?“
Správná odpověď: Proměnná v Sassu existuje pouze během kompilace. Kompilátor její hodnotu napevno vepíše do výsledného CSS a v prohlížeči již proměnná neexistuje (nelze ji za běhu změnit JavaScriptem). Nativní CSS proměnná (--color) žije přímo v DOM stromu prohlížeče, kaskáduje, dědí se a lze ji dynamicky manipulovat skripty i v Media Queries.
