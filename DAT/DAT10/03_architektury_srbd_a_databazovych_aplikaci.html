Proč vznikl ANSI/SPARC? Princip zapouzdření
Cílem ANSI/SPARC je zabránit tomu, aby změna na interní fyzické úrovni (např. přesun na SSD nebo vytvoření nového indexu) vynutila jakoukoli změnu v klientských aplikacích a uživatelských dotazech.
Základní vlastnost SŘBD

Logická a fyzická datová nezávislost

Dva stupně nezávislosti zajišťované mapováním mezi vrstvami ANSI/SPARC

1. Logická datová nezávislost (Logical Data Independence)

Schopnost upravit konceptuální schéma, aniž by bylo nutné měnit existující externí schémata nebo aplikační kód.

  • Praktický příklad: Do tabulky product přidáme nový sloupec warranty_months INT.
  • Mobilní aplikace a webový košík, které tento sloupec nečtou, fungují bez jediné úpravy dál.
  • Nebo rozdělení tabulky vertikální fragmentací: Starým aplikacím poskytneme VIEW simulující původní strukturu.

2. Fyzická datová nezávislost (Physical Data Independence)

Schopnost změnit interní fyzické uložení dat, aniž by došlo ke změně konceptuálního schématu či SQL dotazů.

  • Praktický příklad: DBA vytvoří index CREATE INDEX idx_price ON product(price) nebo přesune data na RAID pole.
  • Konceptuální schéma (tabulky a vztahy) zůstává 100% netknuté.
  • SQL dotaz SELECT * FROM product WHERE price < 500 zůstává identický, pouze se zrychlí jeho exekuce.
Architektura aplikací

2-vrstvá (Klient–Server) vs. 3-vrstvá webová architektura

Proč se u moderních e-shopů ustoupilo od přímého připojení k databázi

Otázka k absolutoriu

2-vrstvá architektura (Tlustý klient / Fat Client)

1. Klientská stanice
Desktop Aplikace
UI + Byznys logika + SQL
→
2. Databázový server
DBMS (Port 3306)
Ukládání dat & Exekuce
  • Aplikace na počítači uživatele se připojuje přímo přes TCP/IP port 3306 k databázovému serveru.
  • Kritické nevýhody:
    • Bezpečnostní riziko: Přihlašovací heslo k DB je zkompilované v klientské aplikaci.
    • Každý klient drží otevřené spojení → server zvládne nanejvýš stovky připojení.
    • Složitá distribuce aktualizací při každé změně byznys logiky.

Privátní síť & ACID
  • Prezentační vrstva: Tenký klient (React/Vue v prohlížeči, mobilní app).
  • Aplikační vrstva: Backend (Node.js, C#, PHP, Java) validuje vstupy a řídí byznys logiku.
  • Databázová vrstva: SŘBD je v privátní podsíti, nepřístupný z internetu.
  • Connection Pooling: Backend sdílí pool desítek stálých spojení pro miliony uživatelů.
Vysoká dostupnost & Výkon

Škálování databází: Replikace a Sharding

Jak udržet e-shop funkční během nákupní špičky Black Friday

Vertikální škálování (Scale-Up)

Zvýšení výkonu jednoho fyzického serveru (více CPU jader, více RAM paměti, rychlejší NVMe disky).

Jednoduché, bez nutnosti měnit kód. Rychle však narazí na fyzické a finanční limity hardwaru.

Replikace (Primary–Replica)

Jeden hlavní server (Primary/Master) přijímá všechny zápisy (INSERT, UPDATE) a synchronizuje je na repliky.

Katalogové dotazy (čtení) se rozdělí mezi desítky Read-Replicas. Zápis objednávek jde pouze do Primary uzlu.

Sharding (Horizontální dělení)

Rozdělení obrovské tabulky na různé nezávislé servery podle klíče (např. podle country_code zákazníka).

Umožňuje uložit miliardy objednávek, ale komplikuje JOIN dotazy napříč různými servery (cross-shard joins).
Architektura nasazení edu_eshop v praxi
V praxi nasazujeme edu_eshop v 3-vrstvé architektuře: SPA frontend komunikuje přes zabezpečené HTTPS JSON REST API s backendem. Backend udržuje Connection Pool do MySQL 8 / MariaDB databáze, která běží v odděleném kontejneru chráněném firewallem.

Zkušební checklist: Okruh absolutoria č. 2 (Architektury)

Souhrn architektury SŘBD a aplikací k ústní zkoušce

Checklist

Znalosti vyžadované u absolutoria

  • Nakreslit a podrobně popsat 3 úrovně ANSI/SPARC (externí, konceptuální, interní).
  • Vysvětlit a uvést praktický příklad pro logickou i fyzickou datovou nezávislost.
  • Porovnat 2-vrstvou (tlustý klient) a 3-vrstvou architekturu (prohlížeč, aplikační server, DB).
  • Vysvětlit, co je Connection Pooling a proč je nezbytný pro vysoké zatížení.
  • Vysvětlit princip Primary-Replica replikace (rozdělení čtení a zápisu) a princip Shardingu.

Klíčové termíny lekce

  • ANSI/SPARC: Standardní trojvrstvá architektura abstrakce databáze (1975).
  • Externí pohled (View): Virtuální tabulka definovaná SQL dotazem pro konkrétní aplikaci.
  • Thin Client (Tenký klient): Aplikace provádějící pouze zobrazení UI (např. HTML/JS v prohlížeči).
  • Connection Pool: Vyrovnávací paměť předpřipravených databázových spojení pro rychlé znovupoužití.
