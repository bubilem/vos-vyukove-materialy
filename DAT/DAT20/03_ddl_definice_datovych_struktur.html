DDL – Definice datových struktur

Příkazy CREATE, ALTER, DROP a TRUNCATE. Správa schémat, tvorba a úpravy tabulek na reálném scénáři edu_eshop.

Klíčové příkazy CREATE, ALTER, DROP, TRUNCATE
Úložný engine InnoDB (ACID compliant)
Okruh zkoušky Otázka č. 8
Správa schématu

Vytvoření a správa databáze

Inicializace databázového prostoru a výběr aktivního schématu

SQL: Založení databáze edu_eshop 
-- Smazání staré verze (idempotentní skript)
DROP DATABASE IF EXISTS `edu_eshop`;

-- Založení nové databáze s plnou Unicode podporou
CREATE DATABASE `edu_eshop`
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_czech_ci;

-- Nastavení jako aktivní pracovní databáze
USE `edu_eshop`;

Důležité klauzule a best practices

  • IF NOT EXISTS / IF EXISTS: Zabraňuje pádu skriptu s chybovou hláškou, pokud schéma již existuje nebo neexistuje.
  • USE db_name;: Kontextový příkaz klienta. Od tohoto okamžiku se tabulky volají přímo (např. product místo edu_eshop.product).
  • Rozdíl SCHEMA vs. DATABASE: V MySQL a MariaDB jsou klíčová slova SCHEMA a DATABASE naprosto rovnocenná synonyma.
Tvorba tabulek

Příkaz CREATE TABLE v praxi

Definice sloupců, výchozích hodnot a úložného engine

Reálné DDL z edu_eshop
CREATE TABLE customer 
CREATE TABLE `customer` (
  `id` INT PRIMARY KEY AUTO_INCREMENT,
  `email` VARCHAR(100) NOT NULL UNIQUE,
  `password_hash` VARCHAR(255) NOT NULL,
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `active` BOOLEAN NOT NULL DEFAULT TRUE
) ENGINE=InnoDB;

Rozbor klíčových komponent

  • PRIMARY KEY AUTO_INCREMENT: Automaticky generovaný identifikátor. Každý nový řádek dostane číslo o 1 vyšší.
  • UNIQUE: Zabraňuje registraci dvou uživatelů se shodnou emailovou adresou.
  • DEFAULT CURRENT_TIMESTAMP: Databáze sama automaticky doplní aktuální systémové datum a čas při vložení řádku.
  • ENGINE=InnoDB: Standardní transakční engine MySQL podporující cizí klíče a zamykání na úrovni řádků (row-level locking).
Změna struktury

Modifikace schématu: ALTER TABLE

Jak bezpečně upravovat existující tabulky bez ztráty dat

Příklady operací ALTER TABLE 
-- 1. Přidání nového sloupce pro věrnostní body
ALTER TABLE `customer`
  ADD COLUMN `loyalty_points` INT UNSIGNED NOT NULL DEFAULT 0;

-- 2. Změna definice existujícího sloupce (rozšíření)
ALTER TABLE `product`
  MODIFY COLUMN `name` VARCHAR(250) NOT NULL;

-- 3. Přejmenování sloupce (CHANGE)
ALTER TABLE `customer_profile`
  CHANGE COLUMN `phone` `phone_number` VARCHAR(25) NULL;

-- 4. Odstranění nepotřebného sloupce
ALTER TABLE `product`
  DROP COLUMN `old_legacy_code`;

Rozdíl: MODIFY vs. CHANGE vs. RENAME

  • MODIFY COLUMN: Mění datový typ nebo integritní omezení sloupce, ale nemění jeho název.
  • CHANGE COLUMN: Dokáže změnit název sloupce i jeho definici současně (vyžaduje zadat starý i nový název).
  • RENAME COLUMN: (Od MySQL 8.0) Čisté přejmenování sloupce bez nutnosti opakovat celý datový typ: RENAME COLUMN phone TO phone_number.
Pozor na krácení datového typu!
Při zkracování sloupce (např. z VARCHAR(100) na VARCHAR(20)) může v přísném SQL módu dojít k chybě, pokud stávající data překračují novou délku.

Rekapitulace

Shrnutí: Zásady práce s DDL

Co si bezpečně zapamatovat do vývojářské praxe

1

Pište idempotentní skripty

Vždy používejte konstrukce CREATE TABLE IF NOT EXISTS a skripty verzujte v migračních nástrojích (např. Flyway, Liquibase).

2

Pozor na DDL v produkci

Všechny DDL příkazy v MySQL způsobují implicitní COMMIT probíhající transakce a mohou zamknout tabulku (metadata lock).

3

TRUNCATE maže bleskově, ale nevratně

Používejte pro promazání dočasných a logovacích tabulek při testování, kde chcete zároveň resetovat AUTO_INCREMENT.
