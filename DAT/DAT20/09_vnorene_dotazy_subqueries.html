Skalární poddotazy

Skalární poddotazy v klauzuli WHERE

Poddotaz vracející právě jednu hodnotu (1 řádek, 1 sloupec)

Produkty s nadprůměrnou cenou 
SELECT 
  `id`, `name`, `price`
FROM `product`
WHERE `price` > (
  -- Vnitřní skalární dotaz vrátí průměr: 9 444,50 Kč
  SELECT AVG(`price`) 
  FROM `product` 
  WHERE `active` = TRUE
)
ORDER BY `price` DESC;

Jak se dotaz zpracuje?

  1. Databáze nejprve samostatně spočítá vnitřní dotaz v závorce: SELECT AVG(price)....
  2. Tento vnitřní dotaz vrátí jediné skalární číslo (např. 9444.50).
  3. Vnější dotaz se přetvoří na: WHERE price > 9444.50.
Chyba: Subquery returns more than 1 row
Pokud pro běžné porovnání (=, >, <) použijete poddotaz, který vrátí více než jeden řádek, dotaz okamžitě zhavaruje s chybou. Pro vícenásobné hodnoty musíte použít operátor IN, ANY nebo ALL!
Množinové poddotazy

Operátory IN, ANY a ALL

Porovnání hodnoty se sadou vrácených výsledků

Otázka u zkoušky
Operátory v praxi nad edu_eshop 
-- 1. Operátor IN: Zákazníci, kteří již nakoupili
SELECT `id`, `email` FROM `customer`
WHERE `id` IN (
  SELECT DISTINCT `customer_id` FROM `orders`
);

-- 2. Operátor > ALL: Dražší než VŠECHNO příslušenství
SELECT `name`, `price` FROM `product`
WHERE `price` > ALL (
  SELECT p.`price`
  FROM `product` p
  JOIN `product_category` pc ON p.`id` = pc.`product_id`
  WHERE pc.`category_id` = 4 -- ID kategorie Příslušenství
);

Rozdíl mezi ANY a ALL

  • x > ANY (...): Hodnota x musí být větší než alespoň jedna hodnota z poddotazu (ekvivalentní k: x > MIN(...)).
  • x > ALL (...): Hodnota x musí být větší než úplně všechny hodnoty ze sady (ekvivalentní k: x > MAX(...)).
  • x = ANY (...): Přesné synonymum pro operátor x IN (...).
Typy poddotazů

Korelované vs. Nekorelované poddotazy

Závislost vnitřního dotazu na řádcích vnějšího dotazu

Výkonnostní rozdíl

Nekorelovaný poddotaz

Je zcela nezávislý na vnějším dotazu. Lze jej vzít a spustit samostatně.

  • Provede se pouze 1× pro celý dotaz.
  • Výsledek se uloží do dočasné paměti a opakovaně používá.
  • Vysoký výpočetní výkon.

Korelovaný poddotaz

Uvnitř poddotazu se odkazujeme na sloupec z vnějšího dotazu (např. outer_p.id).

  • Vyhodnocuje se pro KAŽDÝ řádek vnějšího dotazu znovu!
  • Má-li vnější tabulka 10 000 řádků, vnitřní dotaz se spustí 10 000×!
  • Může způsobit dramatické zpomalení (často lze lépe nahradit pomocí JOIN).
Příklad korelovaného dotazu: Poslední objednávka každého zákazníka
SELECT c.`email`, o1.`id`, o1.`created_at`, o1.`total_price`
FROM `customer` c
JOIN `orders` o1 ON c.`id` = o1.`customer_id`
WHERE o1.`created_at` = (
  -- Vnitřní dotaz závisí na c.id z vnějšího dotazu!
  SELECT MAX(o2.`created_at`)
  FROM `orders` o2
  WHERE o2.`customer_id` = c.`id`
);
Existenční testy

Predikáty EXISTS a NOT EXISTS

Bleskové ověření existence záznamu s optimalizací Short-Circuit

Zákazníci, kteří nikdy nenakoupili (NOT EXISTS) 
SELECT c.`id`, c.`email`
FROM `customer` c
WHERE NOT EXISTS (
  SELECT 1 
  FROM `orders` o
  WHERE o.`customer_id` = c.`id`
);

Proč je EXISTS tak rychlý?

  • Zastaví se při prvním nálezu: Na rozdíl od COUNT() neprochází celou tabulku. Jakmile narazí na první vyhovující záznam, vrátí TRUE a dál nehledá.
  • Nezáleží na sloupcích v SELECTu: Konstrukce SELECT 1 nebo SELECT * uvnitř EXISTS je rovnocenná – databázi zajímá pouze existence řádku, nikoliv přenos dat.
  • Bezpečné s NULL: Na rozdíl od NOT IN (kde přítomnost jediné hodnoty NULL v sadě zneplatní celý dotaz) funguje NOT EXISTS naprosto spolehlivě!
Rekapitulace

Shrnutí: Kdy použít poddotaz a kdy JOIN?

Rozhodování pro zkoušku i optimalizaci v praxi

1

Na porovnání s agregátem: Skalární poddotaz

Hledání entit větších než průměr nebo rovných maximu se bez skalárního poddotazu prakticky neobejde.

2

Na existenci: Preferujte EXISTS

Testování existence vazeb je s EXISTS bezpečnější vůči NULL a často rychlejší než IN.

3

Když potřebujete sloupce z obou: Použijte JOIN

Pokud potřebujete ve výstupu zobrazit atributy z obou tabulek současně, poddotaz ve WHERE vám nepomůže – musíte použít JOIN.
