Otázka u zkoušky

DDL (Data Definition)

Definice a modifikace struktury databáze a tabulek.

  • CREATE TABLE / DATABASE
  • ALTER TABLE
  • DROP TABLE
  • TRUNCATE TABLE

DML (Data Manipulation)

Manipulace se samotnými daty (řádky v tabulkách).

  • INSERT INTO (vkládání)
  • UPDATE ... SET (úprava)
  • DELETE FROM (mazání)

DQL (Data Query)

Čtení a dotazování na uložená data.

  • SELECT ... FROM
  • WHERE, JOIN
  • GROUP BY, ORDER BY
  • (Někdy formálně řazeno pod DML)

DCL (Data Control Language)

Řízení přístupových práv, uživatelů a bezpečnostních rolí:

GRANT SELECT, INSERT ON eshop.* TO 'student'@'%';
REVOKE DROP ON eshop.* FROM 'student'@'%';

TCL (Transaction Control Language)

Správa transakcí a garance vlastností ACID:

START TRANSACTION; → COMMIT; (potvrzení) nebo ROLLBACK; (vrácení zpět do původního stavu).

Desetinná čísla: DECIMAL vs. FLOAT

DECIMAL(M, D): Přesný aritmetický typ s pevnou řádovou čárkou. Ukládá číslice exaktně jako řetězec decimálních hodnot.

Kritická zkoušková otázka: Proč ne FLOAT?
Typy FLOAT a DOUBLE používají binární aproximaci IEEE 754. Například hodnota 0.1 + 0.2 může skončit jako 0.30000000000000004! V účetnictví by vznikaly haléřové chyby. Ceny v edu_eshop: DECIMAL(10,2) (až 99 999 999,99 Kč).

Textové typy, Kódování a Kolace

CHAR vs. VARCHAR a tajemství české diakritiky v utf8mb4

CHAR(N) vs. VARCHAR(N)

  • CHAR(N): Pevná délka. Pokud je řetězec kratší než N, doplní se mezerami.
    Vhodné pro: Kódy států (CHAR(2) jako 'CZ'), rodná čísla, hashe MD5/SHA256 (CHAR(64)).
  • VARCHAR(N): Proměnná délka. Uloží pouze skutečné znaky + 1 až 2 byty pro délku.
    Vhodné pro: Jména (VARCHAR(50)), emaily (VARCHAR(100)).
  • TEXT: Ukládá se mimo hlavní stránku řádku (overflow buffer). Vhodné pro popisy produktů a recenze.

Znaková sada (Charset) & Kolace (Collation)

Charset: Jak se znaky převádí na byty.
Zlatý standard: utf8mb4 (plná podpora Unicode včetně 4bajtových znaků a všech jazyků).

Collation: Pravidla pro porovnávání a řazení textů.

edu_eshop: utf8mb4_czech_ci
_ci = Case Insensitive (nerozlišuje velká/malá písmena při porovnání).
czech = Respektuje českou abecedu (písmeno „CH“ se správně řadí až za „H“, nikoliv mezi „C“ a „D“!).

Datum, Čas a Moderní typy (JSON, ENUM)

Časová razítka, stavy objednávek a flexibilní atributy

DATETIME vs TIMESTAMP

DATE: pouze datum YYYY-MM-DD (např. birth_date).

DATETIME: 8 bytů, rozsah 1000 až 9999. Ukládá přesný čas bez konverze časových zón.

TIMESTAMP: 4 byty, automaticky převádí čas do/z UTC. Pozor: Problém roku 2038 (limit 32bitového celého čísla)!

Výčtový typ ENUM

Povoluje pouze předdefinované textové hodnoty uložené interně jako číselné indexy (1 byte):

-- Tabulka orders v edu_eshop:
`status` ENUM(
  'new', 
  'paid', 
  'shipped', 
  'cancelled'
) NOT NULL DEFAULT 'new'

Typ JSON v MySQL 8

Umožňuje ukládat validní JSON dokument s binární optimalizací pro rychlé vyhledávání bez parsování celého textu:

-- product.attributes
SELECT name,
  attributes->>'$.color' AS barva
FROM product;
BOOLEAN v MySQL
V MySQL a MariaDB je datový typ BOOLEAN (či BOOL) pouze aliasem pro TINYINT(1), kde hodnota 0 reprezentuje FALSE a 1 reprezentuje TRUE.
Rekapitulace & Příprava

Shrnutí: Jak správně volit datové typy

Zásady pro profesionální a čistý databázový návrh

1

Volte nejmenší dostačující typ

Pokud stačí TINYINT (např. hodnocení 1–5), nepoužívejte INT. Šetří to RAM buffer pool a zvyšuje počet řádků na diskovou stránku.

2

Na měny jedině DECIMAL

Nikdy nepoužívejte plovoucí řádovou čárku pro účetní data. DECIMAL(10,2) je sázka na jistotu bez zaokrouhlovacích anomálií.

3

U textů hlídejte délku

Fixní délka = CHAR, proměnná s limitem = VARCHAR, dlouhé volné texty = TEXT. Vždy s kolací utf8mb4_czech_ci.
