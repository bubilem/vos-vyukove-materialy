Integritní omezení & Referenční integrita

Zajištění konzistence a validity dat. Primární klíče, unikátnost, podmínky CHECK a cizí klíče s referenčními akcemi CASCADE, SET NULL a RESTRICT na schématu edu_eshop.

Typy integrity Entitní, Doménová, Referenční
Referenční akce CASCADE, SET NULL, RESTRICT
Okruh zkoušky Otázka č. 9
Architektura integrity

Tři pilíře databázové integrity

Databáze musí aktivně odmítnout nesmyslná a nekonzistentní data

Otázka u zkoušky

1. Entitní integrita

Každý řádek v relaci musí být jednoznačně identifikovatelný.

  • Zajištěno pomocí PRIMARY KEY.
  • Hodnota klíče nesmí být NULL ani duplicitní.

2. Doménová integrita

Hodnota atributu musí odpovídat povolenému typu a rozsahu.

  • Správný datový typ a délka.
  • Klauzule NOT NULL a DEFAULT.
  • Kontrolní výraz CHECK.

3. Referenční integrita

Vztahy mezi tabulkami musí být vždy platné.

  • Zajištěno pomocí FOREIGN KEY.
  • Cizí klíč nesmí odkazovat na neexistující záznam.
Proč svěřit integritu databázi a ne aplikačnímu kódu?
Do databáze často přistupuje více aplikací (web, mobilní aplikace, API, integrační skripty, analytika). Pokud integritu hlídá přímo SŘBD na úrovni engine InnoDB, neexistuje způsob, jak systém obejít a zapsat poškozená data.
Doménová integrita

CHECK, UNIQUE a NOT NULL v edu_eshop

Zajištění věcné správnosti uložených hodnot

Ukázky z edu_eshop.sql 
-- 1. Kontrola nezápornosti ceny a skladu
CREATE TABLE `product` (
  `id` INT PRIMARY KEY AUTO_INCREMENT,
  `price` DECIMAL(10,2) NOT NULL,
  `stock_quantity` INT NOT NULL DEFAULT 0,
  CONSTRAINT `chk_product_price` CHECK (`price` >= 0),
  CONSTRAINT `chk_product_stock` CHECK (`stock_quantity` >= 0)
);

-- 2. Hodnocení pouze 1 až 5 hvězd + unikátní recenze
CREATE TABLE `rating` (
  `id` INT PRIMARY KEY AUTO_INCREMENT,
  `product_id` INT NOT NULL,
  `customer_id` INT NOT NULL,
  `score` TINYINT NOT NULL,
  CONSTRAINT `chk_rating_score` 
    CHECK (`score` BETWEEN 1 AND 5),
  CONSTRAINT `uq_customer_product_rating` 
    UNIQUE (`customer_id`, `product_id`)
);

Rozbor pravidel

  • CHECK (score BETWEEN 1 AND 5): Pokus o vložení skóre 0 nebo 6 skončí chybou: Check constraint 'chk_rating_score' is violated.
  • Složený unikátní klíč: UNIQUE (customer_id, product_id) garantuje, že tentýž zákazník může ohodnotit stejný produkt maximálně jednou!
  • Pojmenovávání omezení: Vždy dávejte omezením explicitní název (např. chk_product_price), aby vývojář v chybové hlášce ihned věděl, co porušil.
Referenční integrita

Definice cizích klíčů (FOREIGN KEY)

Jak propojit tabulky a chránit integritu vazeb 1:1, 1:N a M:N

Syntaxe ALTER TABLE ADD CONSTRAINT 
-- Vztah 1:1 mezi profilem a zákazníkem
ALTER TABLE `customer_profile`
  ADD CONSTRAINT `fk_customer_profile_customer`
  FOREIGN KEY (`customer_id`) 
  REFERENCES `customer` (`id`)
  ON DELETE CASCADE 
  ON UPDATE CASCADE;

-- Sebereferenční stromová hierarchie kategorií
ALTER TABLE `category`
  ADD CONSTRAINT `fk_category_parent`
  FOREIGN KEY (`parent_id`) 
  REFERENCES `category` (`id`)
  ON DELETE SET NULL 
  ON UPDATE CASCADE;

Podmínky pro vytvoření cizího klíče

  • Shodný datový typ: Sloupec cizího klíče musí mít naprosto identický typ a znaménko jako primární klíč (např. oba INT UNSIGNED).
  • Index na rodičovské tabulce: Cílový sloupec musí být PRIMARY KEY nebo mít UNIQUE index.
  • Existující data: V tabulce potomka nesmí před vytvořením vazby ležet žádná hodnota, která neexistuje v rodičovské tabulce.
Referenční akce

Referenční akce: Co se stane při smazání rodiče?

Rozdíl mezi CASCADE, SET NULL a RESTRICT / NO ACTION

Klíčová zkoušková otázka

CASCADE

Automaticky provede stejnou akci na všech závislých řádcích.

  • Smazáním zákazníka zaniká i jeho osobní profil a hodnocení.
  • Smazáním objednávky se automaticky smažou všechny její řádky v order_item.

SET NULL

Závislé řádky zůstanou zachovány, ale hodnota cizího klíče se přepíše na NULL.

  • Podmínka: Sloupec cizího klíče musí povolovat NULL (nesmí být NOT NULL).
  • Ukázka v edu_eshop: Smazáním nadřazené kategorie „Počítače“ se podkategorie „Příslušenství“ nestratí, jen se z ní stane kořenová kategorie (parent_id = NULL).

RESTRICT / NO ACTION

Zákaz operace. SŘBD operaci DELETE/UPDATE okamžitě odmítne s chybou.

  • Účetní a právní ochrana: Zákazníka, který má realizované nákupy v tabulce orders, nelze smazat.
  • Nejprve by musel administrátor vyřešit závislé záznamy.
Kdy zvolit jakou akci v praxi?
Při obhajobě schématu u absolutoria musíte u každé vazby umět zdůvodnit, proč jste nezvolili výchozí RESTRICT, ale např. CASCADE nebo SET NULL, s ohledem na doménovou logiku aplikace!
Rekapitulace

Shrnutí: Integrita v kostce

Kontrolní seznam pro ověření návrhu tabulky

1

Každá tabulka musí mít PRIMARY KEY

Jednoznačná identifikace řádku je základním předpokladem relačního modelu dat a InnoDB úložiště.

2

Používejte CHECK pro byznys limity

Ceny, množství na skladě i hodnocení vždy omezte pomocí CHECK (nezápornost, povolené rozsahy).

3

Vždy explicitně definujte ON DELETE

Nenechávejte cizí klíče bez definice referenční akce. Zvolte vědomě RESTRICT, CASCADE nebo SET NULL.
