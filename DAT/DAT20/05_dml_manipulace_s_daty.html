Vkládání dat

Příkaz INSERT INTO

Jednoduché i hromadné vkládání záznamů (Bulk insert)

Příklady vkládání do edu_eshop 
-- 1. Jednorázové vložení produktu
INSERT INTO `product` 
  (`name`, `price`, `stock_quantity`, `description`)
VALUES 
  ('USB-C Hub 7v1', 899.00, 45, 'Hliníkový adaptér');

-- 2. Hromadný INSERT (Bulk insert - doporučeno!)
INSERT INTO `customer` 
  (`id`, `email`, `password_hash`) 
VALUES
  (1, 'jan.novak@email.cz', '$2y$10$hash1'),
  (2, 'petra.svobodova@seznam.cz', '$2y$10$hash2'),
  (3, 'tomas.dvorak@gmail.com', '$2y$10$hash3');

Proč VŽDY explicitně vyjmenovávat sloupce?

SQL povoluje zkrácený zápis: INSERT INTO product VALUES (1, 'USB Hub', ...);. Tento zápis je však v profesionální praxi přísně zakázán!

  • Pokud v budoucnu přes ALTER TABLE přidáte do tabulky nový sloupec, staré INSERT skripty bez výčtu sloupců okamžitě zhavarují.
  • Neuvedené sloupce s DEFAULT nebo AUTO_INCREMENT se při explicitním výčtu automaticky bezpečně dopočítají.
Výkonnostní výhoda Bulk INSERTu
Vložení 1 000 řádků v jediném příkazu trvá zlomek sekundy, zatímco 1 000 samostatných INSERTů znamená 1 000 síťových round-tripů a disk synchronizací transakčního logu!
Aktualizace dat

Příkaz UPDATE a bezpečnost

Úprava existujících záznamů a hrozba chybějícího WHERE

Otázka u zkoušky
Syntaxe a výpočty v UPDATE 
-- 1. Změna stavu objednávky konkrétního zákazníka
UPDATE `orders`
SET 
  `status` = 'shipped',
  `created_at` = NOW()
WHERE `id` = 3;

-- 2. Plošné zdražení produktů v kategorii o 10 %
UPDATE `product`
SET `price` = ROUND(`price` * 1.10, 2)
WHERE `active` = TRUE;

-- 3. Naskladnění zásob (+ 20 kusů)
UPDATE `product`
SET `stock_quantity` = `stock_quantity` + 20
WHERE `id` = 1;
Noční můra databázisty: UPDATE bez WHERE
Pokud spustíte: UPDATE customer SET active = FALSE; bez klauzule WHERE, deaktivujete všechny zákazníky v celé databázi!

Ochranný mechanismus: Safe Updates

MySQL Workbench a moderní klienti mají standardně aktivní volbu sql_safe_updates = 1. Ta zakáže spuštění UPDATE nebo DELETE, pokud v klauzuli WHERE nepoužijete primární klíč nebo indexovaný sloupec!

SET SQL_SAFE_UPDATES = 0; -- Dočasné vypnutí ochrany

Mazání dat

Příkaz DELETE FROM

Cílené mazání záznamů vs. referenční integrita

Příklady DELETE 
-- 1. Smazání neaktivních zákazníků bez nákupů
DELETE FROM `customer`
WHERE `active` = FALSE 
  AND `id` NOT IN (
    SELECT DISTINCT `customer_id` FROM `orders`
  );

-- 2. Smazání položky z nákupního košíku
DELETE FROM `order_item`
WHERE `order_id` = 1 AND `product_id` = 3;

-- 3. Bezpečné promazání s limitem
DELETE FROM `system_logs`
WHERE `created_at` < '2024-01-01'
ORDER BY `created_at` ASC
LIMIT 500;

Chování DELETE vůči cizím klíčům

  • Smazání záznamu s vazbou CASCADE: Pokud smažeme řádek v orders, databáze sama automaticky smaže i odpovídající záznamy v order_item.
  • Smazání s vazbou RESTRICT: Pokus o DELETE FROM customer WHERE id = 1; skončí chybou:
    Error 1451: Cannot delete or update a parent row: a foreign key constraint fails (`orders`, CONSTRAINT `fk_orders_customer` FOREIGN KEY ...)
Rekapitulace

Shrnutí: Zásady spolehlivého DML

Zlatá pravidla bezpečného programování v databázích

1

Vždy před UPDATE spusťte SELECT

Otestujte si podmínku klauzule WHERE nejprve příkazem SELECT * FROM tabulka WHERE ..., abyste viděli, které řádky skutečně zasáhnete!

2

Používejte transakce

Při rizikových úpravách zahajte transakci: START TRANSACTION;, zkontrolujte změny, a teprve pak napište COMMIT; (při chybě ROLLBACK;).

3

Nepodceňujte triggery

V edu_eshop operace INSERT a DELETE nad tabulkou order_item automaticky přepočítávají celkovou cenu v orders!
