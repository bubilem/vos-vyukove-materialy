Zastoupené typy relačních vazeb

  • Vazba 1:1: customer ↔ customer_profile se sdíleným primárním klíčem (vertikální fragmentace).
  • Hierarchická sebereference 1:N: category.parent_id → category.id pro modelování neomezeného stromu podkategorií.
  • Vazba M:N: product ↔ category realizovaná vazební tabulkou product_category.
  • Asociační entita s historií: order_item dekomponuje vztah mezi objednávkou a produktem a fixuje historickou prodejní cenu.

Normalizace vs. Řízená Denormalizace

  • Důsledná 3. normální forma (3NF): Žádný neklíčový atribut není tranzitivně závislý na primárním klíči.
  • Denormalizace 1 (Historická cena): order_item.unit_price záměrně kopíruje cenu v momentě nákupu pro ochranu účetnictví.
  • Denormalizace 2 (Rychlé počítadlo): category.product_count je agregát synchronizovaný databázovými triggery.

Proč rozdělit účet a profil na dvě tabulky?

  • Kardinalita 1:1 s volitelností (0..1): Zákazník může mít vytvořený účet, ale profil vyplní až při prvním nákupu.
  • Vertikální fragmentace: Úzká tabulka customer umožňuje rychlejší vyhledávání a indexaci při přihlašování.
  • Referenční integrita: Cizí klíč s ON DELETE CASCADE garantuje, že při smazání účtu automaticky zanikne i osobní profil.
SQL • Dotaz na zákazníky s profilem i bez 
-- Výběr aktivních zákazníků s volitelným profilem (LEFT JOIN)
SELECT 
  c.id, c.email, c.active,
  cp.first_name, cp.last_name, cp.phone
FROM `customer` c
LEFT JOIN `customer_profile` cp ON c.id = cp.customer_id
WHERE c.active = 1;

Proč DECIMAL místo FLOAT/DOUBLE?
Plovoucí řádová čárka způsobuje zaokrouhlovací chyby (např. 0.1 + 0.2 ≠ 0.3). Pro peněžní částky se striktně používá přesný typ DECIMAL(10,2).
SQL • Sebereferenční Self-JOIN (Strom kategorií) 
-- Spojení tabulky category na samu sebe (Self-JOIN)
SELECT 
  sub.id,
  sub.name AS podkategorie,
  COALESCE(parent.name, '[Hlavní kategorie]') AS nadkategorie
FROM `category` sub
LEFT JOIN `category` parent ON sub.parent_id = parent.id
ORDER BY parent.name, sub.name;
SQL • Filtrování přes NoSQL JSON atributy 
-- Operátor ->> extrahuje hodnotu z JSON jako text
SELECT 
  name, price,
  attributes->>'$.color' AS barva,
  CAST(attributes->>'$.ram_gb' AS UNSIGNED) AS ram
FROM `product`
WHERE attributes->>'$.color' = 'Black';

Klíčová didaktická zásada: Historická cena
Proč nesmíme v objednávkách číst cenu z tabulky product? Pokud prodejce za rok zdraží produkt z 500 na 700 Kč, staré účetnictví by se zpětně přepočítalo. Proto je v order_item.unit_price uložena historická hodnota vteřiny nákupu!

Referenční pravidla ON DELETE

  • Objednávka → Položky (CASCADE): Smazáním celé stornované objednávky zaniknou všechny její dílčí řádky.
  • Zákazník → Objednávka (RESTRICT): Zákazníka nelze z databáze smazat, pokud má existující účetní doklady (ochrana auditní stopy).
  • Produkt → Položka (RESTRICT): Zboží, které si v minulosti někdo zakoupil, nelze z databáze fyzicky odstranit (řeší se soft-delete: active = false).
SQL • Souhrn objednávky s mezisoučtem 
-- Výpočet ceny položek s použitím historické nákupní ceny unit_price
SELECT 
  oi.order_id,
  p.name AS produkt,
  oi.quantity AS mnozstvi,
  oi.unit_price AS cena_za_kus,
  (oi.quantity * oi.unit_price) AS celkem_polozka
FROM `order_item` oi
JOIN `product` p ON oi.product_id = p.id
WHERE oi.order_id = 1;

Složený unikátní klíč: UNIQUE(customer_id, product_id)
Zabraňuje tomu, aby tentýž zákazník napsal více recenzí k jednomu produktu a manipuloval s hodnocením.

Agregace hodnocení v praxi

Pro výpočet průměru využíváme funkci AVG() s funkcí ROUND(). Pokud produkt nemá žádné recenze, AVG() vrátí NULL, což ošetřujeme pomocí COALESCE().

SQL • Výpočet průměrného hodnocení produktů 
-- Agregace hodnocení přes AVG() a ošetření produktů bez recenzí
SELECT 
  p.id, p.name,
  COALESCE(ROUND(AVG(r.score), 2), 0.00) AS prumer_znamka,
  COUNT(r.id) AS pocet_recenzi
FROM `product` p
LEFT JOIN `rating` r ON p.id = r.product_id
GROUP BY p.id, p.name
ORDER BY prumer_znamka DESC;

Programovatelnost: Triggery & Pohledy

Automatická synchronizace agregátů a abstraktní vrstva pro dotazování

TRIGGER • VIEW

6 Databázových triggerů v modelu

  • trg_category_product_count_insert: Zvýší product_count po přidání vazby v product_category.
  • trg_category_product_count_delete: Sníží product_count po smazání vazby.
  • trg_category_product_count_update: Převede počítadlo při změně kategorie produktu.
  • trg_order_item_after_insert/update/delete: Automaticky sečte SUM(quantity * unit_price) a zapíše do orders.total_price.

2 Připravené pohledy (VIEW)

  • v_product_catalog: Spojuje produkt, jeho kategorie přes GROUP_CONCAT a průměrné hodnocení s počtem recenzí.
  • v_order_summary: Kompletní manažerský report objednávek se jménem zákazníka, telefonem, počtem položek a celkovou částkou.
SQL • Trigger pro automatický přepočet ceny objednávky 
CREATE TRIGGER `trg_order_item_after_insert`
AFTER INSERT ON `order_item`
FOR EACH ROW
BEGIN
  UPDATE `orders`
  SET `total_price` = (
    SELECT COALESCE(SUM(`quantity` * `unit_price`), 0)
    FROM `order_item` WHERE `order_id` = NEW.`order_id`
  )
  WHERE `id` = NEW.`order_id`;
END;

Slovník pojmů – Referenční databáze

Kardinalita 1:1 (One-to-One)
Vazba, kde jednomu záznamu odpovídá maximálně jeden záznam v druhé tabulce. V edu_eshop realizována mezi customer a customer_profile přes sdílený primární klíč.
Sebereference (Self-referencing relation)
Vazba tabulky na sebe samu. V tabulce category sloupec parent_id odkazuje na id nadřazené kategorie, což umožňuje tvořit stromovou hierarchii libovolné hloubky.
Vazba M:N (Many-to-Many)
Vztah, kdy jedna entita odpovídá mnoha druhým a naopak. V relační databázi se dekomponuje pomocí asociační tabulky (product_category).
Řízená denormalizace
Záměrné porušení normální formy pro vyšší výkon nebo integritu historie. V order_item.unit_price chrání historickou cenu; v category.product_count udržuje rychlý čítač přes triggery.
Trigger (Databázová spoušť)
Uložená procedura automaticky vyvolaná operací INSERT, UPDATE nebo DELETE na tabulce. Zajišťuje integritu agregátů bez závislosti na aplikačním kódu.
Pohled (VIEW)
Virtuální tabulka definovaná uloženým SQL dotazem. Zjednodušuje složité JOIN dotazy a sjednocuje logiku pro klientské aplikace.
