Historie a motivace

Zrození moderních Windows (Windows NT)

Jak tým Davea Cutlera nahradil zastaralou linii DOS/Windows 9x

Historie NT
Konec éry MS-DOS a Windows 9x
16-bit / Zastaralé

Původní Windows 1.0 až 95/98/Me byly pouhou grafickou nadstavbou nad 16bitovým systémem MS-DOS:

  • Žádná paměťová ochrana: Pád jediné aplikace mohl přepsat data jádra a způsobit okamžité zhroucení celého PC (modrá smrt / BSOD).
  • Kooperativní multitasking: Pokud program dobrovolně nepředal řízení procesoru, celý operační systém zamrzl.
  • Absence bezpečnosti: Neexistovalo skutečné oddělení uživatelských účtů ani přístupová práva k souborům na disku FAT16/FAT32.
  • Omezený hardware: Neschopnost efektivně adresovat více než stovky megabajtů RAM a nulová podpora pro vícejádrové CPU (SMP).
Zásadní rozdíl: Windows NT 3.1 (1993) byly napsány zcela od nuly. Neobsahovaly ani řádek kódu z MS-DOSu.
Projekt Windows New Technology (NT)
Dave Cutler (DEC)

V roce 1988 najal Microsoft architekta Davea Cutlera (autora systému VMS z DEC) a stanovil nekompromisní cíle:

  • Přenositelnost (Portability): Jádro psáno v C, nezávislé na architektuře (x86, MIPS, Alpha, dnes x86-64 a ARM64).
  • Preemptivní multitasking: Plánovač jádra sám přiděluje časová kvanta procesoru. Žádná aplikace nemůže uzurpovat systém.
  • SMP (Symmetric Multiprocessing): Podpora pro více fyzických CPU a jader na jedné základní desce.
  • C2 Bezpečnost (DoD Orange Book): Bezpečnostní audit, striktní ACL práva, šifrované ukládání hesel a ochrana objektů.
  • Dědictví dodnes: Dnešní Windows 10, 11 i Windows Server 2022/2025 jsou přímými potomky tohoto jádra (NT verze 10.0).
Klíčový koncept: Důsledné hardwarové oddělení User Mode (Ring 3) od Kernel Mode (Ring 0).

Jádro systému
  • Object Manager (Ob): Vše v NT je objekt (soubory, procesy, vlákna, klíče registru). Poskytuje jednotné handle deskriptory, řízení přístupu a počítání referencí.
  • Virtual Memory Manager (Mm): Řídí 64bitový virtuální adresní prostor, překlad adres přes stránkovací tabulky (PTE), working set procesů a odkládání (paging).
  • Process and Thread Manager (Ps): Spravuje životní cyklus procesů a vláken (struktury EPROCESS a ETHREAD), přiděluje ID procesů.
  • I/O Manager (Io): Zpracovává asynchronní vstupy/výstupy pomocí paketů IRP (I/O Request Packets). Umožňuje vrstvení ovladačů zařízení.
  • Security Reference Monitor (SRM): Vynucuje bezpečnostní politiku přímo v Kernel Mode. Porovnává přístupový token procesu s ACL deskriptorem objektu.
Proč hybridní jádro? Ovladače grafiky (GDI/DirectX) byly přesunuty do win32k.sys v Ring 0 kvůli maximálnímu výkonu grafického rozhraní.
Uživatelská vrstva & Konfigurace

Klíčové procesy a systémový registr

Role csrss.exe, lsass.exe a centrální stromové databáze Registry

Konfigurace
Kritické systémové procesy Windows
User Space
  • smss.exe (Session Manager): Úplně první uživatelský proces spuštěný jádrem. Startuje subsystém Win32, nastavuje proměnné prostředí a spravuje stránkovací soubory.
  • csrss.exe (Client/Server Runtime): Zajišťuje správu konzolových oken (conhost), vytváření a ukončování procesů a vláken subsystému Win32.
  • lsass.exe (Local Security Authority): Ověřuje přihlašovací údaje uživatelů, hesla (NTLM / Kerberos), vystavuje bezpečnostní tokeny a obsluhuje Active Directory.
  • services.exe (Service Control Manager - SCM): Spouští systémové démony a služby na pozadí, řídí jejich závislosti a restarty při selhání.
Ukončení procesu: Násilné ukončení csrss.exe nebo lsass.exe ve Správci úloh vyvolá okamžitou modrou smrt (CRITICAL_PROCESS_DIED).
Architektura Windows Registry
Hierarchická DB

Centrální hierarchická databáze konfiguračních údajů operačního systému, ovladačů a aplikací:

  • Hlavní větve (Hives):
    • HKEY_LOCAL_MACHINE (HKLM): Globální nastavení platné pro celý počítač, hardware, ovladače a systémový software.
    • HKEY_CURRENT_USER (HKCU): Profil a preference právě přihlášeného uživatele (dynamický alias do HKEY_USERS).
    • HKEY_CLASSES_ROOT (HKCR): Asociace přípon souborů a registrace COM objektů.
  • Fyzické uložení: Binární soubory hive v C:\Windows\System32\config\ (SYSTEM, SOFTWARE, SAM, SECURITY).
Datové typy: REG_SZ (textový řetězec), REG_DWORD (32bitové celé číslo), REG_BINARY (surová binární data).

Klíčové poznatky a otázky

Přehled architektury Windows NT a otázky k zamyšlení

Kontrolní otázky

1. Proč hybridní jádro?

Vysvětlení, proč Windows NT kombinují modulární strukturu Executive služeb s umístěním grafického subsystému (win32k.sys) do Kernel Mode kvůli vykreslovacímu výkonu.

2. Role HAL a ntoskrnl

Pochopení významu knihovny hal.dll pro izolaci zbytku jádra od odlišností procesorových patic, APIC řadičů přerušení a čipsetů základních desek.

3. Význam lsass a csrss

Znalost funkcí klíčových subsystémových procesů (autentizace uživatelů a generování bezpečnostních tokenů vs. řízení Win32 prostředí a konzolí).

4. Otázka k procvičení a zamyšlení

„Popište strukturu Windows Executive, princip stránkování virtuální paměti (pagefile.sys vs. standby list) a vysvětlete, jakou roli hraje Object Manager při řízení přístupu k systémovým prostředkům.“
