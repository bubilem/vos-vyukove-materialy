Architektura Windows & Jádro NT

Vnitřní stavba rodiny Windows NT: historický odkaz Davea Cutlera, vrstva hardwarové abstrakce HAL, NT Kernel a NT Executive, subsystém Win32 (csrss.exe), bezpečnostní subsystém LSASS a koncepce systémového registru (Windows Registry).

Historie NT

Konec éry MS-DOS a Windows 9x

Původní Windows 1.0 až 95/98/Me byly pouhou grafickou nadstavbou nad 16bitovým systémem MS-DOS:

  • Žádná paměťová ochrana – pád jedné aplikace shodil celý počítač.
  • Kooperativní multitasking a absence skutečného oddělení práv uživatelů.
  • Neschopnost obsluhovat vícejádrové procesory (SMP) a enterprise servery.

Projekt Windows New Technology (NT)

V roce 1988 najal Microsoft architekta Davea Cutlera (autora VMS systému z DEC):

  • Cíle návrhu: Přenositelnost (x86, MIPS, Alpha, dnes ARM64), stabilita, symetrický multiprocesing (SMP), podpora POSIXu a bezpečnost splňující standard C2 (oranžová kniha DoD).
  • Zavedení hybridního jádra s přísným oddělením User Mode (Ring 3) a Kernel Mode (Ring 0).
  • Dnešní Windows 10 a 11 jsou přímými potomky tohoto jádra (NT verze 10.0).

Komponenty NT Executive

  • Object Manager (Ob): Vše v NT je objekt (soubory, procesy, klíče registru). Poskytuje jednotné deskriptory, řízení přístupu a počítání referencí.
  • Virtual Memory Manager (Mm): Řídí 64bitový virtuální adresní prostor, stránkování a mapované soubory.
  • Process and Thread Manager (Ps): Vytváří a ukončuje procesy a vlákna.
  • I/O Manager (Io): Zpracovává asynchronní požadavky na zařízení pomocí paketů IRP (I/O Request Packets).
  • Security Reference Monitor (SRM): Vynucuje bezpečnostní politiku a ACL přístupová práva v Kernel Mode.

Konfigurace

Kritické systémové procesy Windows

  • smss.exe (Session Manager): První uživatelský proces spuštěný jádrem. Startuje subsystém Win32 a spravuje stránkovací soubory.
  • csrss.exe (Client/Server Runtime): Zajišťuje správu konzolových oken, vláken a procesů subsystému Win32.
  • lsass.exe (Local Security Authority): Ověřuje přihlášení uživatelů, hesla, generuje bezpečnostní tokeny a spolupracuje s Active Directory.
  • services.exe (Service Controller): Spravuje spouštění a běh služeb na pozadí.

Architektura Windows Registry

Centrální hierarchická databáze konfiguračních údajů OS a aplikací:

  • Hlavní větve (Hives):
    • HKEY_LOCAL_MACHINE (HKLM): Nastavení platné pro celý počítač a hardware.
    • HKEY_CURRENT_USER (HKCU): Profil a preference právě přihlášeného uživatele.
    • HKEY_CLASSES_ROOT (HKCR): Asociace přípon souborů a COM objekty.
  • Fyzicky uloženo v binárních souborech v C:\Windows\System32\config\.

Otázky z architektury Windows NT u zkoušky

Absolutorium

1. Proč hybridní jádro?

Vysvětlení, proč Windows NT kombinují modulární strukturu Executive služeb s umístěním grafického subsystému (win32k.sys) do Kernel Mode.

2. Role HAL

Pochopení významu knihovny hal.dll pro izolaci zbytku jádra od odlišností procesorových patic a čipsetů základních desek.

3. Význam lsass a csrss

Znalost funkcí klíčových subsystémových procesů (autentizace uživatelů a generování bezpečnostních tokenů vs. řízení Win32 prostředí).

4. Otázka u zkoušky

„Popište strukturu Windows Executive a vysvětlete, jakou roli hraje Object Manager při řízení přístupu k systémovým prostředkům.“
