Klíčový mechanismus

1. Programmed I/O (PIO)

CPU samo čte nebo zapisuje každý bajt či slovo přes registry řadiče:

  • Instrukce IN a OUT na porty x86 sběrnice.
  • Extrémní zatížení procesoru (100% zátěž CPU při diskovém přenosu).
  • Používá se dnes jen pro velmi pomalé sběrnice (sériové porty, klávesnice).

2. Memory-Mapped I/O (MMIO)

Registry periferie jsou namapovány přímo do fyzického adresního prostoru procesoru:

  • Ke čtení a zápisu na kartu stačí standardní instrukce MOV na vyhrazenou paměťovou adresu.
  • Využívají moderní sběrnice PCI Express a grafické karty.

3. Direct Memory Access (DMA)

Řadič periferie přenáší celé bloky dat přímo do fyzické RAM bez účasti CPU:

  • CPU pouze předá DMA řadiči: zdrojovou adresu, cílovou adresu v RAM a délku bloku.
  • Během gigabajtového přenosu může CPU vykonávat programy.
  • Po dokončení přenosu DMA řadič vyvolá přerušení (IRQ).

Základní dělení I/O zařízení v unixových a NT systémech

Otázka u zkoušky

Bloková zařízení (Block Devices)

  • Přenášejí data v pevných blocích (512 B, 4 KiB sektory).
  • Podporují náhodný přístup (Random Access / Seek) – lze číst libovolný blok nezávisle na ostatních.
  • Vždy využívají vyrovnávací paměť v RAM (Buffer Cache / Page Cache).
  • Příklady: Pevné disky, SSD, NVMe, USB flash disky (/dev/sda, /dev/nvme0n1).

Znaková zařízení (Character Devices)

  • Přenášejí data jako sekvenční proud bajtů (Stream of characters).
  • Nepodporují náhodný přístup: Nelze provést lseek() (nemá smysl skočit doprostřed klávesového toku).
  • Typicky bez systémové mezipaměti nebo s malým FIFO bufferem.
  • Příklady: Klávesnice, myš, sériové linky, terminály (/dev/tty), generátory náhody (/dev/urandom).
Vývoj a stabilita

Kde mají běžet ovladače: Kernel vs. User Mode

Windows Driver Frameworks (WDF) a trend přesunu ovladačů do User Space

WDF Architektura

Kernel-Mode Driver Framework (KMDF)

Ovladač běží v Ring 0 jako součást jádra (.sys ve Windows, moduly .ko v Linuxu):

  • Nutné pro zařízení vyžadující přímou obsluhu hardwarových přerušení a extrémní propustnost (grafické karty, NVMe řadiče disku).
  • Riziko: Chybný ukazatel v ovladači způsobí okamžitý pád systému (BSOD / Kernel Panic). Historicky bylo přes 70 % pádů Windows způsobeno ovladači třetích stran!

User-Mode Driver Framework (UMDF / FUSE)

Ovladač běží jako běžný proces v Ring 3:

  • Vhodné pro zařízení připojená přes standardní sběrnice (USB senzory, tiskárny, chytré karty, síťové adaptéry Wi-Fi).
  • Výhoda: Pokud ovladač zhavaruje, systém jednoduše restartuje proces ovladače. Počítač ani ostatní programy nespadnou.
  • Linux FUSE (Filesystem in Userspace): Umožňuje psát ovladače souborových systémů (např. SSHFS, NTFS-3G) v uživatelském prostoru.

Terminál • Ovladače
bash • Inspekce načtených modulů jádra v Linuxu

$ lsmod | grep -E "e1000e|nvme|usb_storage"

    Select-Object FriendlyName, InstanceId, Status

    Select-Object -First 6

Klíčové znalosti k absolutoriu

Zkušební otázky z I/O subsystému a ovladačů

Absolutorium

1. Princip DMA řadiče

Vysvětlení, jak DMA řadič uvolňuje výpočetní kapacitu procesoru tím, že přenáší data přímo do RAM bez instrukcí CPU.

2. Bloková vs. Znaková zařízení

Přesné vymezení rozdílů: práce v pevných blocích s náhodným přístupem a mezipamětí (disky) vs. proudový sekvenční tok bez seeku (klávesnice).

3. KMDF vs. UMDF

Zdůvodnění, proč moderní operační systémy přesouvají ovladače do User Mode (stabilita systému, izolace chyb před BSOD).
