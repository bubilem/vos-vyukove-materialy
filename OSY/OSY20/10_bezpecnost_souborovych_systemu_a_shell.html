Oprávnění souborů

POSIX oprávnění a speciální bity (SUID, SGID, Sticky)

Tradiční unixový bezpečnostní model v devíti bitech

Klíčová látka

Tři trojice bitů (User / Group / Others)

  • Read (r = 4): Čtení obsahu souboru / čtení seznamu souborů v adresáři.
  • Write (w = 2): Modifikace obsahu souboru / přidávání a mazání souborů v adresáři.
  • Execute (x = 1): Spuštění souboru jako programu / vstup do adresáře (průchod cestou).
  • Příklad: chmod 755 skript.sh → rwxr-xr-x (vlastník plná práva, ostatní čtení a spuštění).

Tři speciální bity (Čtvrtá trojice)

  • SUID (Set User ID, hodnota 4000): Program se spustí s oprávněními vlastníka souboru, nikoli uživatele, který jej spustil (např. /usr/bin/passwd běží jako root, aby mohl zapsat nové heslo do /etc/shadow).
  • SGID (Set Group ID, hodnota 2000): Program běží s právy skupiny. U adresáře: nově vytvořené soubory automaticky dědí skupinu adresáře.
  • Sticky Bit (hodnota 1000): U adresářů (typicky /tmp s právy 1777): soubor v adresáři smí smazat pouze jeho skutečný vlastník nebo root.
Jemnozrnné řízení

Access Control Lists (ACL)

Když tři kategorie (vlastník, skupina, svět) nestačí enterprise požadavkům

Otázka k zamyšlení

Omezení základního POSIX modelu

Představte si požadavek: „Uživatel Alice smí číst, uživatel Bob smí zapisovat, skupina Účetní smí číst a nikdo jiný nemá přístup.“

  • Základní model rwxrwxrwx toto neumí vyřešit (umožňuje definovat pouze jednu jedinou skupinu).
  • Řešení: Access Control Lists (ACL) – seznam záznamů (ACE), kde lze explicitně definovat práva pro neomezený počet jednotlivých uživatelů a skupin.

Srovnání ACL v Linuxu a Windows

  • Linux POSIX ACL: Nástroje getfacl a setfacl. Přidává položky k inodu jako rozšířené atributy (xattr):
    setfacl -m u:alice:r,u:bob:rw projekt/
  • Windows NTFS ACL: Srdce zabezpečení Windows. Každý soubor má Security Descriptor obsahující:
    • DACL (Discretionary ACL): Seznam povolených (Allow) a odepřených (Deny) oprávnění. Explicitní Deny má vždy přednost před Allow!
    • SACL (System ACL): Pravidla pro auditování úspěšných a neúspěšných pokusů o přístup k souboru.

Shell Cyklus

Kroky vykonání příkazu v Shellu (Bash)

  1. Čtení řádku (Read): Načtení řetězce ze standardního vstupu (klávesnice).
  2. Lexikální analýza a parsování: Rozdělení na slova, identifikace operátorů (|, >, &&, ;).
  3. Expanze (Expansions):
    • Proměnné: $USER se nahradí za jméno uživatele.
    • Substituce příkazů: $(date) se nahradí výstupem příkazu.
    • Wildcardy (Globbing): *.txt se nahradí seznamem souborů.
  4. Vyhodnocení vestavěných příkazů (Builtins): Příkazy jako cd, exit, export musí běžet v shellu samotném (nemohou být externí binárkou, protože musí změnit stav shellu).
  5. Vyhledání v PATH, fork() a execve(): Spuštění externího programu.

Standardní proudy a přesměrování

  • Každý nově vytvořený proces dostává tři otevřené souborové deskriptory:
    • 0 (stdin): Standardní vstup (výchozí klávesnice).
    • 1 (stdout): Standardní výstup (výchozí obrazovka).
    • 2 (stderr): Chybový výstup (výchozí obrazovka, nezávislý na stdout).
  • Přesměrování operátory:
    • cmd > soubor.txt (přepíše stdout).
    • cmd >> soubor.txt (připojí na konec stdout).
    • cmd 2> err.log (přesměruje pouze chyby).
    • cmd > all.log 2>&1 (spojí stdout i stderr do jednoho souboru).

Příkazy setfacl, icacls a řetězení v PowerShellu

Terminál • ACL & Shell
bash • Nastavení a zobrazení Linux ACL 
# Udělení práva čtení a zápisu pro uživatele 'student'
$ setfacl -m u:student:rw /shared/projekt/

# Zobrazení detailního ACL seznamu
$ getfacl /shared/projekt/
# file: shared/projekt/
# owner: root
# group: admin
user::rwx
user:student:rw-
group::r-x
mask::rwx
other::---
powershell • Inspekce NTFS ACL oprávnění přes Get-Acl 
# Zobrazení přístupových pravidel (Access Rules) složky
PS> (Get-Acl "C:\Data").Access |
    Select-Object IdentityReference, FileSystemRights, AccessControlType

# Výpis výstupu:
IdentityReference   FileSystemRights   AccessControlType
-----------------   ----------------   -----------------
NT AUTHORITY\SYSTEM FullControl        Allow
BUILTIN\Users       ReadAndExecute     Allow

Kontrolní otázky

1. Význam SUID bitu

Vysvětlení, jak SUID umožňuje běžnému uživateli dočasně vykonávat privilegované operace a jaká z toho plynou bezpečnostní rizika.

2. Výhody ACL

Zdůvodnění potřeby ACL pro jemnozrnné řízení přístupu více nezávislých uživatelů a skupin k jednomu adresáři.

3. Práce se standardními proudy

Pochopení deskriptorů 0, 1, 2 a schopnost správně přesměrovat chybové hlášky a výstupy pomocí operátorů shellu.
