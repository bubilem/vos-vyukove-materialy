Kontext a intuice

Proč procesor vůbec potřebuje režimy?

Co by se stalo, kdyby mohl kterýkoliv program dělat naprosto cokoliv

Základní princip
Divoký západ bez pravidel (MS-DOS)

V pionýrských dobách (MS-DOS, Windows 3.11/95) procesor žádné striktní bariéry neměl. Program mohl sáhnout na libovolný kousek operační paměti RAM i fyzického disku.

  • Počítačová hra měla chybu v kódu: Přepsala paměť operačního systému a celý počítač okamžitě zamrzl.
  • Jediné řešení: Zmáčknout fyzické tlačítko Reset na bedně počítače a začít znovu.
  • Virus či nešikovný kód: Mohl poslat přímý příkaz disku a nenávratně zformátovat data.
Žádná ochrana paměti = pád jednoho programu položí celý PC
Životní metafora: Restaurace

Představte si moderní počítač jako fungující restauraci:

Host u stolu (User Mode / Aplikace):
Může jíst své jídlo a číst lístek. Nesmí sám vběhnout do kuchyně se sekerou a sahat do rozpálené pánve.
Číšník (Systémové volání / Syscall):
Přebírá objednávku hosta, zkontroluje, zda má host peníze a zda je jídlo v nabídce.
Kuchyně a šéfkuchař (Kernel Mode / Jádro OS):
Jedině on má přístup k nožům, ohni a zásobám (hardware). Uvaří pokrm a předá ho zpět.
Zlaté pravidlo: Režimy nevymyslel software, vynucuje je fyzický křemík CPU
Ochranu procesoru nevymyslel Bill Gates ani Linus Torvalds. Je to hardwarová funkce mikroprocesoru (Intel, AMD, ARM). Samotný křemíkový čip procesoru ví, v jakém režimu zrovna běží, a pokud se neoprávněný program pokusí o zakázanou akci, procesor ho okamžitě hardwarově zastaví.
Architektura systému

Dva světy: User Mode vs. Kernel Mode

Běžné hřiště aplikací versus neomezená kontrola nad veškerým hardwarem

Zásadní rozdělení
User Mode (Uživatelský režim)
Ring 3 • Omezená práva
  • Kdo zde běží: 99 % programů – webový prohlížeč (Chrome), hry, Word, Discord, Spotify, vaše skripty v Pythonu i kalkulačka.
  • Co smí: Počítat matematiku, číst a zapisovat výhradně do své vlastní přidělené virtuální paměti RAM.
  • Co NESMÍ: Přímo přistupovat k fyzickému hardwaru (SSD, grafická karta, síťová karta) ani nahlížet do paměti ostatních programů.
  • Co se stane při chybě: Systém aplikaci bez milosti ukončí („Program přestal pracovat“ / Segmentation fault). Zbytek počítače, Windows i ostatní otevřené aplikace běží dál!
Bezpečná izolace: Pád aplikace neohrozí operační systém
Kernel Mode (Režim jádra)
Ring 0 • Plná práva
  • Kdo zde běží: Samotné jádro operačního systému (ntoskrnl.exe ve Windows, vmlinuz v Linuxu) a nízkoúrovňové ovladače (grafika NVIDIA/AMD, Wi-Fi, diskový řadič).
  • Co smí: Naprosto VŠECHNO. Má neomezený přímý přístup k fyzické RAM, registrům CPU, diskům i síťovým kartám.
  • Co hlídá: Přiděluje paměť procesům, plánuje běh na jádrech procesoru a chrání hardware před zneužitím.
  • Co se stane při chybě: Totální kolaps. Nad jádrem už nikdo není, kdo by chybu zachránil. Systém se okamžitě zastaví: Modrá smrt (BSOD) ve Windows nebo Kernel Panic v Linuxu.
Maximální moc = maximální riziko: Chyba v jádře sundá celý počítač

Proč má procesor 4 kruhy, ale moderní Windows a Linux používají jen dva

Architektura x86_64
Ring 0 • Kernel Mode
Jádro OS, ovladače hardware • Absolutní práva
Aktivně využito
Ring 1 • Ovladače zařízení
Původní návrh Intelu (1982) • Dnes se nepoužívá
Nevyužito
Ring 2 • Služby operačního systému
Původní návrh pro souborové systémy • Dnes se nepoužívá
Nevyužito
Ring 3 • User Mode
Aplikace, hry, prohlížeče • Přísně omezená práva
Aktivně využito

Proč moderní systémy ignorují Ring 1 a 2?

Inženýři Intelu v roce 1982 (procesor 80286) navrhli 4 vrstvy jako cibuli. V praxi se však ukázaly dva zásadní problémy:

  • Přenositelnost (Portabilita): Jiné procesory (ARM, MIPS, RISC-V) měly historicky pouze 2 režimy (User a Supervisor). Kdyby Windows NT nebo Linux používaly 4 kruhy, nemohly by snadno běžet na jiných čipech!
  • Výkon procesoru: Přepínání mezi 4 úrovněmi zpomalovalo běh systému.
Co je to privilegovaná instrukce?
Příkazy jako HLT (uspi procesor) nebo CLI (zakaž reakci na myš a klávesnici). Pokud se je pokusí spustit program v Ring 3, procesor mu to nedovolí a vyvolá hardwarovou chybu General Protection Fault (#GP).

Systémové volání (Syscall): Most mezi světy

Jak si aplikace slušně žádá operační systém o přístup k hardwaru

Přechodový mechanismus

Základní rébus: Jak program bez práv něco uloží?

Program v User Mode nesmí sáhnout na disk. Jak tedy textový editor uloží soubor nebo prohlížeč odešle data přes Wi-Fi?

  • Odpověď: Program musí požádat jádro OS, aby to udělalo za něj.
  • Tomuto oficiálnímu požadavku se říká Systémové volání (System Call / Syscall).
  • Je to jako bankovní přepážka s neprůstřelným sklem: Aplikace podá formulář (požadavek), úředník (jádro) ho prověří a vydá hotovost (provede zápis).
Syscall je jediná povolená brána z User Mode do Kernel Mode

Evoluce rychlosti: Od přerušení k bleskovému skoku

Způsob, jakým se aplikace dohaduje s procesorem, prošel obrovským vývojem:

Starý způsob: Softwarové přerušení (INT 0x80)
Procesor musel uložit hromadu stavů do paměti a projít tabulku přerušení IDT. Trvalo to kolem 1 000 taktů CPU.
Moderní 64bit způsob: Instrukce SYSCALL • SYSRET
Procesor skočí přímo na předem nachystanou adresu jádra uloženou ve speciálním registru CPU. Trvá to pouhých několik desítek taktů!

Běžný operační systém provede desítky tisíc systémových volání za jedinou sekundu (při každém pohnutí myší, načtení webu nebo přehrání zvuku).

Názorný proces

Příběh jednoho kliknutí na „Uložit soubor“

Co se stane v počítači během zlomku milisekundy od stisku tlačítka k zápisu na SSD

6 fází přechodu
1 User Mode (Ring 3)
Aplikace volá funkci
Uživatel v Poznámkovém bloku klikne na „Uložit“. Aplikace zavolá standardní programátorskou funkci (např. WriteFile() ve Windows nebo write() v Linuxu).
2 User Mode (Ring 3)
Příprava formuláře
Systémová knihovna naplní registry CPU: do jednoho registru dá číslo operace (např. „zápis“), do dalších adresu textu v RAM a identifikátor otevřeného souboru.
3 Přepnutí do Ring 0
Instrukce syscall
Procesor v jediném taktu hardwarově přepne úroveň z Ring 3 na Ring 0, uzamkne uživatelský zásobník a skočí na zabezpečený vstupní bod jádra.
4 Kernel Mode (Ring 0)
Bezpečnostní prověrka
Jádro zkontroluje: Má uživatel právo zapisovat do této složky? Není disk plný? Nejde o pokus poškodit systémové soubory Windows? Pokud ne, schválí zápis.
5 Ovladač • Hardware
Fyzický zápis na disk
Jádro předá data ovladači diskového řadiče (NVMe/SATA). Řadič pošle elektrické signály do paměťových buněk SSD a potvrdí dokončení zápisu.
6 Návrat do Ring 3
Instrukce sysret
Jádro instrukcí sysret přepne procesor zpět do bezpečného User Mode. Aplikace dostane zprávu: „Zapsáno 1 024 bajtů“ a klidně pokračuje.
Architektura ARM64

Jak to dělají mobily: ARM Exception Levels

Od aplikací v iPhonech a Androidu až po neproniknutelný „Bezpečný svět“

ARM64 • EL0 až EL3

Procesory ARM v telefonech i v počítačích Apple Mac (M1/M2/M3/M4) nepoužívají označení „kruhy“, nýbrž Úrovně výjimek (Exception Levels • EL):

EL0 • User Mode
Běžné aplikace (Instagram, TikTok, mobilní hry). Obdoba Ring 3.
EL0 • Aplikace
EL1 • Kernel Mode
Operační systém (jádro Androidu, jádro iOS / macOS). Obdoba Ring 0.
EL1 • OS Jádro
EL2 • Hypervisor
Virtualizace • Správa virtuálních počítačů (KVM, Apple Hypervisor).
EL2 • Virtualizace
EL3 • Secure Monitor (TrustZone)
Tajná komnata procesoru • Nejvyšší možná úroveň hardwaru.
EL3 • Secure World
Proč studenta nadchne EL3 (TrustZone)?

Představte si, že záškodník kompletně hackne telefon a získá nejvyšší práva Root v operačním systému Android (úroveň EL1).

Dostane se k vašemu otisku prstu a platební kartě? NE!

  • V úrovni EL3 běží zcela izolovaný mikroprocesorový subsystém zvaný TrustZone (v iPhonech zvaný Secure Enclave).
  • Zde jsou uloženy biometrické vzorky otisků (Touch ID) a obličeje (Face ID).
  • Zde jsou šifrovací klíče pro Apple Pay a Google Wallet.
  • Ani samotné jádro Androidu do této paměti nevidí. Pouze se zeptá: „Je přiložený prst pravý?“ a TrustZone odpoví pouze: „Ano / Ne“.
Reálný svět a havárie

Pád aplikace vs. Modrá smrt (BSOD)

Proč systém chybu v aplikaci přežije, ale chyba v ovladači zastaví celou planetu

Případová studie

Scénář A: Chyba v User Mode (Ring 3)

V počítačové hře nebo v prohlížeči Chrome programátor špatně spočítal ukazatel v paměti a sáhl mimo přidělený prostor (Null Pointer Exception):

  • Hardware procesoru detekuje neoprávněný přístup a vyvolá výjimku.
  • Jádro v Ring 0 zakročí: „Tento proces porušil pravidla izolace.“
  • Jádro proces jednoduše ukončí a uvolní jeho paměť RAM.
  • Výsledek: Okno hry zmizí, plocha funguje, hudba hraje dál. Běžný pád programu.

Scénář B: Chyba v Kernel Mode (Ring 0)

Ovladač grafické karty nebo antiviru běží v Ring 0 a udělá stejnou chybu (sáhne na neplatnou adresu paměti):

  • Kdo zachrání situaci? NIKDO. V Ring 0 není žádná vyšší autorita.
  • Pokud by systém pokračoval, mohl by náhodně přepsat data na pevném disku nebo poškodit souborový systém.
  • Jediná bezpečná možnost je okamžitě nouzově zastavit CPU.
  • Výsledek: Obrazovka zmodrá: Blue Screen of Death (BSOD).
Globální lekce pro IT svět: Incident CrowdStrike (Červenec 2024)
19. července 2024 zkolabovalo 8,5 milionu počítačů na celém světě – zastavila se letiště, nemocnice i banky. Důvod? Bezpečnostní software CrowdStrike Falcon běžel jako ovladač v Ring 0 (aby mohl monitorovat nízkoúrovňové útoky). Rutinní aktualizace definic obsahovala chybný soubor, který v Ring 0 způsobil čtení neplatné paměti. Protože k chybě došlo v jádře, systém Windows neměl jinou volnost než okamžitě spadnout do BSOD. Ponaučení: Kód v Kernel Mode musí být psán s 1 000× větší zodpovědností než běžná aplikace!
Praktická diagnostika

Kde vidíme Kernel Mode v praxi?

Tři diagnostické triky, které si může vyzkoušet každý student na svém počítači

Praktické nástroje
Windows Správce úloh

Stiskněte Ctrl + Shift + Esc, přejděte na záložku Výkon → Procesor. Klikněte pravým tlačítkem do grafu a zaškrtněte:

„Zobrazit časy jádra“ (Kernel times)

V grafu přibude tmavší křivka. Ta vám ukáže, kolik procent výkonu CPU zrovna tráví v Ring 0 obsluhou ovladačů a systémových volání!

Sysinternals ProcMon

Legendární bezplatný nástroj od Microsoftu (autor Mark Russinovich):

  • Zobrazuje v reálném čase každý jednotlivý syscall, který programy posílají jádru.
  • Uvidíte přesně, jaké soubory na disku aplikace otevírá a které klíče v registrech čte.
  • Skvělý nástroj, když zjišťujete, proč program hlásí „Přístup odepřen“.
Linux příkaz strace

V Linuxu (nebo WSL ve Windows) stačí napsat:

$ strace cat soubor.txt

Na obrazovce se vyvalí desítky volání: openat(), read(), write(), close(). Uvidíte anatomii programu přímo na úrovni jádra!

Diagnostická hádanka: Proč má procesor 100 % v časech jádra?
Pokud na počítači nic neděláte a graf CPU ukazuje vysoké vytížení v časech jádra (Kernel Time), nejde o zaseknutou hru ani prohlížeč. Znamená to problém v Ring 0: buďto vadný ovladač neustále cyklí, dochází k chybám čtení na poškozeném disku, nebo hardware posílá záplavu přerušení (Interrupt Storm).

Klíčové poznatky & Kvíz pro začátečníky

Ověřte si, že rozumíte nejdůležitějším bariérám v operačním systému

Kvíz • Zkouška
Častý mýtus studentů
„Když v systému Windows kliknu pravým tlačítkem a zvolím Spustit jako správce (Run as Administrator), program začne běžet v Ring 0 (Kernel Mode).“
Inženýrská realita
Kdepak! Program stále běží v Ring 3 (User Mode). Má pouze speciální bezpečnostní token, se kterým mu jádro povolí provádět citlivější systémová volání (např. instalaci softwaru či změnu času).
Q1 Proč Chrome spouští každý otevřený panel jako samostatný proces v User Mode?
Odpověď: Pokud se na jedné stránce zasekne skript nebo stránka zhavaruje, spadne pouze ten jeden konkrétní proces. Ostatní panely i celý prohlížeč fungují dál bez přerušení.
Q2 Co přesně se stane, pokud obyčejný program v C zkusí spustit instrukci HLT (uspi CPU)?
Odpověď: Procesor instrukci odmítne vykonat, protože v Ring 3 je zakázaná. Vyvolá hardwarovou výjimku General Protection Fault (#GP) a jádro neposlušný program okamžitě zabije.
Q3 Proč se útočník s plnými právy Root v Androidu nedostane k otisku vašeho prstu?
Odpověď: Jádro Androidu běží pouze v úrovni EL1, zatímco biometrické senzory a klíče jsou zamčené v hardwarově odděleném světě EL3 (TrustZone), kam jádro nemá přístup.

Slovník pojmů • Režimy OS a privilegia

User Mode Ring 3
Uživatelský režim procesoru
Režim s omezenými právy, ve kterém běží běžné aplikace. Zabraňuje přímému přístupu k hardwaru a izoluje paměť jednotlivých procesů.
Kernel Mode Ring 0
Režim jádra / Supervisor
Plně privilegovaný stav procesoru. Kód jádra a ovladačů má neomezený přístup k veškeré paměti RAM i fyzickému hardwaru počítače.
Syscall Přechod
Systémové volání (System Call)
Oficiální programátorská žádost aplikace o službu operačního systému (např. otevření souboru, síťová komunikace či vykreslení na displej).
sysret Instrukce
Návrat ze systémového volání
Blesková instrukce na x86_64, která přepne procesor z Ring 0 zpět do Ring 3 a předá řízení původnímu uživatelskému programu.
Privilegovaná instrukce CPU Hard
Instrukce vyhrazená jádru
Instrukce CPU (např. HLT, CLI, STI, změna registrů CR0-CR4), kterou smí vykonat pouze kód v Ring 0. Pokus o spuštění v Ring 3 vede k pádu programu.
General Protection Fault #GP Výjimka
Chyba obecné ochrany
Hardwarová výjimka procesoru x86 vyvolaná při pokusu programu překročit svá oprávnění nebo zapsat do chráněné paměti jádra.
BSOD Kolaps
Blue Screen of Death (Modrá smrt)
Nouzové zastavení operačního systému Windows při neopravitelné chybě v Kernel Mode (Ring 0), aby se zabránilo poškození dat na disku.
TrustZone / EL3 ARM64
Secure World na architektuře ARM
Hardwarově izolovaná doména procesorů ARM chránící biometrická data (otisk prstu, obličej) a šifrovací klíče k platebním kartám.
