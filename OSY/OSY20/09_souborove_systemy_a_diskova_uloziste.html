Virtual File System (VFS)

Jak operační systém sjednocuje disky, flash paměti i síťová úložiště

Klíčová vrstva

Role vrstvy VFS

Aplikace nevolá funkce specifické pro ext4 nebo NTFS. Volá univerzální funkce POSIX / Win32:

  • VFS představuje objektově orientované rozhraní v jazyce C uvnitř jádra.
  • Definuje čtyři základní objekty:
    • Superblock: Popisuje celý připojený souborový systém (velikost bloku, celková kapacita, volné bloky).
    • Inode: Reprezentuje konkrétní soubor a jeho metadata (velikost, práva, časová razítka, ukazatele na data).
    • Dentry (Directory Entry): Propojuje jméno souboru s číslem inodu (rychlá vyrovnávací paměť pro cesty).
    • File: Reprezentuje otevřený soubor v běžícím procesu (aktuální offset čtení f_pos).

Jednotný strom vs. Písmena jednotek

  • Unix / Linux: Jediný globální kořenový adresář /. Libovolný disk nebo síťový svazek se připojuje (Mount) do libovolného podadresáře (např. /mnt/data).
  • Windows NT: Historické dědictví disketových písmen C:\, D:\. Interně však NT Object Manager používá také strom (\Device\HarddiskVolume1), který je písmenům přiřazen přes symbolické odkazy.

Otázka u zkoušky

Co je to Inode (Index Node)?

Datová struktura pevné velikosti (typicky 256 bajtů) na disku popisující soubor:

  • Obsahuje: UID vlastníka, GID skupiny, přístupová práva (rwxr-xr-x), velikost souboru v bajtech, čas vytvoření/změny/přístupu (atime, mtime, ctime).
  • Obsahuje ukazatele na datové bloky (v ext4 pomocí rozsahů / Extents – souvislých bloků paměti pro bleskové čtení velkých souborů).
  • Důležité: Inode neobsahuje jméno souboru! Jméno je uloženo v datovém bloku nadřazeného adresáře jako pár (jméno, číslo inodu).
  • Díky tomu mohou existovat pevné odkazy (Hard Links) – více různých jmen ukazujících na stejný inode.

Organizace v blokových skupinách (Block Groups)

  • Disk je rozdělen na blokové skupiny, aby se minimalizoval pohyb mechanické hlavičky HDD.
  • Každá skupina obsahuje: kopii superbloku, bitmapu bloků (volné bloky), bitmapu inodů a tabulku inodů.
Windows úložiště

NTFS a Master File Table ($MFT)

Všechno v NTFS je soubor – i samotný popis disku

NTFS • MFT

Master File Table ($MFT)

Srdcem NTFS je lineární relační tabulka záznamů (každý záznam má 1024 bajtů):

  • Každému souboru a adresáři odpovídá alespoň jeden záznam v $MFT.
  • Všechny vlastnosti souboru jsou uloženy jako atributy:
    • $STANDARD_INFORMATION: Časová razítka, DOS atributy (skrytý, systémový).
    • $FILE_NAME: Jméno souboru (podpora Unicode a 8.3 zkrácených názvů).
    • $SECURITY_DESCRIPTOR: Kompletní Access Control List (ACL oprávnění).
    • $DATA: Samotný datový obsah souboru.
  • Resident Data: Pokud je soubor velmi malý (pod cca 700 bajtů), uloží se přímo do záznamu v $MFT bez alokace diskových clusterů!

Pokročilé vlastnosti NTFS

  • Alternativní datové proudy (ADS): Soubor může mít více datových proudů (např. soubor.txt:tajne_data). Využívá se pro označení stažených souborů z internetu (Zone.Identifier).
  • Řídké soubory (Sparse Files): Úspora místa pro soubory plné nul (nealokují se fyzické bloky).
  • Komprese a šifrování: Průhledná LZNT1 komprese a EFS (Encrypting File System).
Integrita dat

Žurnálování: Ochrana před havárií při výpadku proudu

Jak princip Write-Ahead Logging eliminuje zdlouhavé kontroly disku

Otázka u zkoušky

Problém nekonzistence (Staré FAT a ext2)

Zápis souboru vyžaduje několik samostatných zápisů na disk: alokovat blok v bitmapě, zapsat data, aktualizovat inode a zapsat jméno do adresáře:

  • Pokud v polovině této sekvence dojde k výpadku napájení, disk zůstane v nekonzistentním stavu (ztracené clustery, křížově propojené soubory).
  • Při startu musel běžet program fsck nebo chkdsk, který hodiny skenoval celý disk.

Princip žurnálování (Write-Ahead Logging)

  1. Záznam záměru (Journal Write): Jádro nejdříve zapíše plánované změny metadat do vyhrazeného kruhového žurnálu na disku.
  2. Commit záznamu: Do žurnálu se zapíše potvrzení, že transakce je kompletní.
  3. Skutečný zápis: Metadata se zapíší na svá trvalá místa v souborovém systému.
  4. Zotavení po pádu (Crash Recovery): Při bootu jádro pouze projde žurnál. Dokončené transakce přehraje (Replay), nedokončené zahodí. Zotavení trvá zlomek sekundy i u terabajtových disků!

Absolutorium

1. Účel vrstvy VFS

Pochopení role virtuálního souborového systému pro jednotný přístup k různorodým souborovým systémům přes společné datové struktury.

2. Inode a Hard Linky

Schopnost vysvětlit strukturu inodu a zdůvodnit, proč pevný odkaz (Hard Link) sdílí stejný inode a proč jej nelze vytvořit přes hranice různých diskových oddílů.

3. Význam žurnálu

Popis transakčního žurnálování (Write-Ahead Logging) a způsobu rychlého zotavení po nekorektním vypnutí počítače.

4. Otázka u zkoušky
