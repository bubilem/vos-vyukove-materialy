Bezpečnostní koncepty

Tři pilíře systémové bezpečnosti: AAA

Základní model ověřování identity, práv a odpovědnosti

Klíčový koncept

1. Autentizace (Kdo jsi?)

Ověření deklarované identity uživatele nebo procesu:

  • Hesla s kryptografickým solením (SHA-512, bcrypt, Argon2 v /etc/shadow).
  • Asymetrické klíče (SSH ed25519/RSA).
  • Vícefaktorová autentizace (MFA, PAM moduly).
  • Biometrické ověření (Windows Hello, Touch ID).

2. Autorizace (Co smíš?)

Rozhodnutí, zda má autentizovaná identita oprávnění provést operaci:

  • Ověření práv při každém pokusu o otevření souboru, soketu nebo spuštění procesu.
  • Přístupové matice, skupiny, POSIX oprávnění, Access Control Lists (ACL).
  • Role-Based Access Control (RBAC).

3. Auditování (Co jsi dělal?)

Prokazatelný a nepopiratelný záznam všech bezpečnostních událostí:

  • Záznamy o neúspěšných přihlášeních (brute-force detekce).
  • Záznamy o použití privilegovaných příkazů (sudo logy, auditd).
  • Windows Security Event Log a auditování přístupu k citlivým objektům.
Řízení přístupu

Diskreční (DAC) vs. Povinné (MAC) řízení přístupu

Proč tradiční oprávnění vlastník-skupina-ostatní nestačí moderním serverům

Otázka u zkoušky

DAC (Discretionary Access Control)

Tradiční model známý z Unixu (rwx) i běžných Windows:

  • Vlastník rozhoduje: Uživatel, který soubor vytvořil, má plné právo změnit jeho oprávnění (chmod 777).
  • Zranitelnost: Pokud webový server běží pod uživatelem www-data a útočník jej zkompromituje, může číst a měnit všechny soubory patřící tomuto uživateli nebo spouštět nebezpečné binárky.
  • Uživatel root / Administrator obchází veškerá DAC omezení.

MAC (Mandatory Access Control – SELinux / AppArmor)

Striktní systémové politiky vynucované přímo jádrem bez ohledu na přání uživatele:

  • I když je útočník root, politika jádra mu neumožní přepsat systémové konfigurační soubory nebo otevřít nepovolený síťový port.
  • SELinux (Security-Enhanced Linux): Každému procesu i souboru je přiřazen bezpečnostní kontext (User:Role:Type:Level). Proces typu httpd_t smí číst pouze soubory typu httpd_sys_content_t.
Oprávnění

Princip minimálních privilegií a eskalace práv

Srovnání Linuxového sudo a Windows User Account Control (UAC)

Least Privilege

Princip nejmenších výsad (Least Privilege)

Každý program i uživatel by měl běžet s nejnižší možnou úrovní oprávnění nutnou k vykonání své práce:

  • Běžná práce (prohlížení webu, psaní dokumentů) nikdy nesmí probíhat pod účtem správce/root.
  • Oddělení systémových účtů pro každou službu zvlášť (webový server má vlastní účet, databáze má vlastní účet).
  • Zamezení laterálnímu pohybu útočníka: Průnik do jedné služby neumožní automatické ovládnutí ostatních.

Mechanismus sudo vs. UAC

  • Linux sudo: Záznam v /etc/sudoers definuje, jaké konkrétní příkazy smí uživatel spustit s právy roota po zadání vlastního hesla. Všechny akce jsou striktně logovány.
  • Windows UAC (User Account Control): Správce se přihlašuje se dvěma bezpečnostními tokeny (omezený a administrátorský). Běžné aplikace běží s omezeným tokenem. Pokus o změnu systému vyvolá dialog na chráněné ploše (Secure Desktop).
Praktická bezpečnost

Diagnostika SELinuxu a auditních logů

Ověřování kontextů a sledování bezpečnostních zamítnutí v CLI

Terminál • Bezpečnost
bash • Inspekce kontextů SELinux a auditd 
# Zjištění aktuálního stavu SELinuxu (Enforcing / Permissive)
$ sestatus

# Zobrazení bezpečnostních kontextů souborů přepínačem -Z
$ ls -lZ /var/www/html/
-rw-r--r--. 1 root root system_u:object_r:httpd_sys_content_t:s0 index.html

# Hledání bezpečnostních zamítnutí (AVC denials) v logu auditd
$ sudo ausearch -m avc -ts recent
powershell • Inspekce bezpečnostních politik a UAC 
# Kontrola nastavení úrovně UAC v registrech
PS> Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" |
    Select-Object EnableLUA, ConsentPromptBehaviorAdmin, PromptOnSecureDesktop

# Audit neúspěšných přihlášení (Event ID 4625)
PS> Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625} -MaxEvents 5 |
    Select-Object TimeCreated, Message
