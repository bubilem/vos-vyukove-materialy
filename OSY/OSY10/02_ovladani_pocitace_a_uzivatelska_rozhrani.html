Typologie rozhraní

CLI vs. TUI vs. GUI

Tři generace interakce člověka s operačním systémem

Evoluce

1. CLI (Command Line)

Příkazový řádek v textovém terminálu (Bash, PowerShell, zsh):

  • Minimální spotřeba RAM a CPU, funguje přes úzké pásmo (SSH).
  • Snadná automatizace a řetězení příkazů přes roury (|).
  • Vyžaduje znalost syntaxe a parametrů příkazů.

2. TUI (Text User Interface)

Pseudografické rozhraní v terminálu využívající ANSI/VT100 kódy a knihovnu ncurses:

  • Ovládání šipkami, tabulátorem a klávesovými zkratkami.
  • Typické pro správu BIOS/UEFI, mc (Midnight Commander), htop.
  • Funguje spolehlivě i v nouzovém režimu a přes SSH bez X serveru.

3. GUI (Graphical UI)

Grafické okenní prostředí ovládané myší a dotykem (WIMP – Windows, Icons, Menus, Pointer):

  • Intuitivní pro běžné uživatele, okamžitá vizuální zpětná vazba.
  • Vysoká spotřeba paměti, nutnost grafických ovladačů a compositing engine.
  • Těžší na vzdálenou automatizaci oproti CLI.
Programové rozhraní

Systémová volání (System Calls)

Jediná oficiální brána ze světa aplikace do jádra operačního systému

Klíčový koncept

Jak probíhá systémové volání

Aplikace v uživatelském režimu (User Mode) nemůže přímo číst disk ani poslat TCP paket:

  1. Aplikace zavolá standardní C funkci (např. read(), write()).
  2. Knihovna uloží číslo syscallu a argumenty do procesorových registrů (rax, rdi na x86_64).
  3. Procesor vykoná privilegovanou instrukci (syscall na x86_64 / svc na ARM).
  4. CPU hardwarově přepne do Kernel Mode a skočí na tabulku obsluhy jádra.
  5. Jádro ověří práva a parametry, vykoná operaci a vrátí výsledek zpět do User Space.

API vs. ABI (Application Binary Interface)

  • API (Application Programming Interface): Zdrojová úroveň (hlavičkové soubory .h, funkce jako printf()). Zajišťuje přenositelnost zdrojového kódu (kompatibilita při rekompilaci).
  • ABI (Application Binary Interface): Binární úroveň (volací konvence, velikost struktur v bajtech, zarovnání, čísla syscallů). Zajišťuje, že zkompilovaná binárka poběží bez rekompilace.
  • POSIX standard: Definuje jednotné API pro Unixové systémy (Linux, macOS, BSD).
Architektura služeb

Procesy na pozadí a správa relací

Oddělení uživatelské interakce od nepřetržitého běhu systémových úloh

Systémové služby

Démoni (Unix) & Windows Services

Procesy bez připojeného řídicího terminálu a bez grafického rozhraní běžící na pozadí:

  • Startují typicky během bootu systému před přihlášením uživatele.
  • Zajišťují síťové služby (SSH server sshd, webserver nginx, časovou synchronizaci chrony).
  • Jejich výstup je přesměrován do systémového logu (journald, Syslog, Windows Event Log).

Uživatelská relace (Session Management)

Při přihlášení uživatele OS vytvoří izolovanou relaci:

  • Bezpečnostní kontext: Uživatelský token / UID, GID, seznam přístupových skupin.
  • Proměnné prostředí: PATH, HOME, USER, LANG.
  • Víceuživatelský přístup: Jeden systém může současně obsluhovat desítky uživatelů přes SSH a lokálního uživatele na GUI displeji.
Praktická diagnostika

Trasování systémových volání v reálném čase

Sledování komunikace mezi aplikací a jádrem nástrojem strace

Terminál • strace
bash • Trasování volání jádra pomocí strace 
# Spuštění příkazu 'cat' s odchytáváním souborových a paměťových syscallů
$ strace -e trace=openat,read,write,close cat /etc/hostname

# Výstup zachycený strace z přepnutí do Kernel Mode:
openat(AT_FDCWD, "/etc/hostname", O_RDONLY) = 3
read(3, "vos-server\n", 131072)          = 11
write(1, "vos-server\n", 11)             = 11
close(3)                                = 0
powershell • Analýza procesů a relací 
# Zobrazení procesů rozdělených podle SessionId (0 = služby, 1+ = uživatelé)
PS> Get-Process | Select-Object Id, ProcessName, SessionId, CPU |
    Sort-Object SessionId -Descending | Select-Object -First 8

# Zjištění stavu systémových služeb (Windows Services)
PS> Get-Service | Where-Object Status -eq "Running" |
    Select-Object Name, DisplayName, StartType | Select-Object -First 6
Shrnutí & Zkouškový checklist

Klíčové znalosti k absolutoriu

Shrnutí témat a zkušební otázky z ovládání a rozhraní OS

Absolutorium

1. Výhody CLI v enterprise

Schopnost zdůvodnit, proč jsou serverové systémy spravovány přes CLI (skriptovatelnost, determinismus, nízká režie, bezpečnost a auditovatelnost příkazů).

2. Mechanismus Syscall

Detailní popis přechodu z User Mode do Kernel Mode: hardwarová instrukce, registry CPU, tabulka obsluhy jádra a návrat hodnoty.

3. Rozdíl API vs. ABI

Vysvětlení rozdílu mezi kompatibilitou na úrovni zdrojového kódu (API / POSIX) a kompatibilitou na úrovni binárních spustitelných souborů (ABI).

4. Otázka u zkoušky

„Popište, jaký je rozdíl mezi uživatelskou relací a systémovou službou (démonem) z hlediska životního cyklu a oprávnění.“
