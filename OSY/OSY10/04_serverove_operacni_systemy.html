Serverové operační systémy

Architektura a správa operačních systémů pro nepřetržitý 24/7 provoz v datacentrech: headless režim bez GUI, správa systémových služeb (systemd), vysoká dostupnost (HA), virtualizace (Type 1 a Type 2 hypervizory) a kontejnerizace.

Infrastruktura

1. Bezhlavý provoz (Headless Operation)

Produkční servery nemají připojený monitor, klávesnici ani myš:

  • Žádná zátěž paměti grafickým rozhraním – úspora stovek MB až GB RAM.
  • Menší plocha zranitelnosti (Attack Surface) – v systému nejsou webové prohlížeče, multimediální kodeky ani grafické knihovny.
  • Veškerá konfigurace probíhá vzdáleně přes zabezpečený protokol SSH nebo WinRM / PowerShell Remoting.

2. Spolehlivost a škálování

Podpora náročného enterprise hardwaru a architektur:

  • NUMA (Non-Uniform Memory Access): Optimalizace přístupu k paměti na vícesocketových deskách s desítkami jader.
  • ECC paměti: Hardwarová detekce a oprava jednobitových chyb RAM za běhu.
  • Hot-swap komponenty: Výměna pevných disků a napájecích zdrojů bez vypnutí OS.
  • Žurnálové a spolehlivé FS: ZFS, Btrfs, ReFS, XFS s kontrolními součty dat.

Otázka u zkoušky

Role systemd a architektura jednotek (Units)

Jako první proces (PID 1) spuštěný jádrem řídí celý boot a životní cyklus služeb:

  • Paralelní start: Služby startují souběžně díky soketové aktivaci (Socket Activation), což zkracuje boot na jednotky sekund.
  • Typy unit souborů: .service (démoni), .socket (síťové sokety), .target (skupiny stavů), .timer (náhrada cronu).
  • Automatický restart: Monitorování pádů a automatický restart havarovaných služeb (Restart=on-failure).
  • Izolace přes cgroups: Omezení maximální spotřeby RAM a CPU pro konkrétní službu.

Ekvivalent ve Windows: SCM (Service Control Manager)

  • Centrální správa služeb (services.msc a PowerShell cmdlety *-Service).
  • Startovací typy: Automatic, Delayed Start, Manual, Disabled.
  • Běh pod vyhrazenými systémovými účty: NT AUTHORITY\SYSTEM, NetworkService, LocalService.

Hypervizory vs. Operační kontejnery

Srovnání virtualizace celého OS a odlehčené izolace na úrovni jádra

Klíčové srovnání

Virtualizace přes Hypervizor

Běh několika nezávislých celých operačních systémů (Guest OS) na jednom fyzickém stroji (Host):

  • Type 1 (Bare-metal): Běží přímo na hardwaru (VMware ESXi, Proxmox / KVM, Microsoft Hyper-V). Maximální výkon a stabilita.
  • Type 2 (Hosted): Běží jako aplikace nad běžným OS (VirtualBox, VMware Workstation). Vhodné pro vývoj a testování.
  • Každý virtuální stroj má vlastní jádro, ovladače a přidělenou virtuální RAM.

Kontejnerizace (Docker, Podman, LXC)

Izolace aplikací v rámci jediného sdíleného jádra hostitelského OS:

  • Linux Namespaces: Oddělení pohledu na procesy (PID), síťové karty (NET), uživatele (UID) a přípojné body (MNT).
  • Control Groups (cgroups): Měření a tvrdé limity spotřeby RAM, jader CPU a rychlosti diskových I/O operací.
  • Start kontejneru v milisekundách, minimální režie, vysoká hustota nasazení.
Serverová praxe

Administrace služeb v Linuxu a Windows

Příkazy systemctl, journalctl a PowerShell v enterprise prostředí

CLI • Správa služeb
bash • Práce se službami přes systemd 
# Kontrola stavu webového serveru a jeho cgroup limitů
$ sudo systemctl status nginx

# Aktivace automatického startu po bootu a okamžité spuštění
$ sudo systemctl enable --now nginx

# Sledování chybových logů služby v reálném čase
$ sudo journalctl -u nginx -f --no-pager
powershell • Vzdálená správa služeb 
# Zjištění služeb nastavených na automatický start
PS> Get-Service | Where-Object StartType -eq "Automatic" |
    Select-Object Name, Status, DisplayName

# Bezpečný restart služby a ověření nového PID
PS> Restart-Service -Name "W3SVC" -PassThru |
    Select-Object Name, Status
Shrnutí & Zkouškový checklist

Klíčové znalosti k absolutoriu

Shrnutí zásad serverových operačních systémů

Absolutorium

1. Výhody Headless režimu

Schopnost zdůvodnit odstranění grafického subsystému ze serveru (úspora operační paměti, redukce plochy pro zranitelnosti, stabilita).

2. Architektura systemd

Pochopení principu PID 1, definice unit souborů, správa závislostí a paralelní bootování pomocí socketové aktivace.

3. Hypervizory vs. Kontejnery

Přesné vysvětlení rozdílu mezi Type 1 hypervizorem (vlastní jádro pro každý VM) a kontejnerizací (sdílené jádro, izolace přes namespaces a cgroups).

4. Otázka u zkoušky

„Vysvětlete, jaké mechanismy jádra Linuxu umožňují existenci kontejnerů typu Docker a jak zabránit tomu, aby jeden kontejner vyčerpal veškerou paměť serveru.“
